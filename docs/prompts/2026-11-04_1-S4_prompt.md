## Роль и цель

Ты — программист шага S4 плана «Книжный режим». S3 сделал лист и разворот на вендоренном
StPageFlip, кнопки «‹/›», перетаскивание мышью и позицию чтения. Твоя работа — озвучить
перелистывание: короткий синтезированный WebAudio-шорох, разный вперёд и назад, с
выключателем «Звук», который помнит выбор; при отказе WebAudio книга листается молча и
не ломается. Звуковых файлов в репозитории не появляется (`docs/plans/1-book-reader.md:54`).
Результат — код в двух файлах шага, зелёный `npm run verify` и инструментальные
доказательства из §5 (на слух агент не проверяет — см. В1).

Контракт шага, выписанный из §S4 (`docs/plans/1-book-reader.md:91-94`) — по нему в конце
сверяется ревью:

- **C1.** Перелистывание озвучено коротким синтезированным шорохом, вперёд и назад по-разному.
- **C2.** Есть выключатель, он помнит выбор в `localStorage`.
- **C3.** Звук синтезируется WebAudio, файлов `.mp3`/`.wav` в репозитории нет.
- **C4.** При отказе WebAudio книга продолжает листаться молча.
- **C5.** `npm run verify` → 0/0 и прогон четырёх ручных условий: звук совпадает с
  анимацией, при `prefers-reduced-motion` выключен, двойного звука при быстром листании
  нет, `AudioContext` создаётся только после клика.
- **C6.** Постановка прошла `check_task_prompt.py` (сделано постановщиком, G5).

### Решения, принятые постановкой (менять нельзя; оспаривать — вопросом владельцу)

**R1. Точка запуска звука.** Звук вешается на `changeState === 'flipping'` (F4.2) плюс
собственное `pointerup` для перетаскивания (F4.3, F4.7). На событие `flip` звук НЕ вешается:
это конец анимации (F4.1), звук там опоздает на 700 мс. Фаза 4 плана
(`docs/BOOK-READER-PLAN.md:303`) называет событием синхронизации `flip` — это расхождение
плана с библиотекой, оно фиксируется в отчёте, а `flip` остаётся за S3 (счётчик, позиция,
`disabled`).

**R2. Направление листания** (в событиях его нет, F4.9) — порядок приоритета:
(1) `pendingDir` = `-1`/`+1`, который ставят наши кнопки непосредственно перед
`flipPrev()`/`flipNext()`; (2) для перетаскивания — знак горизонтального смещения:
`dx < 0` (тащим влево) — вперёд, `dx > 0` — назад; (3) иначе половина сцены по `pointerdown`:
правая — вперёд, левая — назад; (4) иначе вперёд. `pendingDir` сбрасывается после
использования. Клавиатуре S5 достаточно ставить `pendingDir` в своём обработчике.

**R3. Числа звука.** Вперёд: полоса 900–2600 Гц (факт F5), центр `f0 = √(900·2600) ≈ 1530 Гц`,
добротность `Q = f0/(2600−900) ≈ 0.9`. Назад: полоса 600–1800 Гц (`f0 ≈ 1039 Гц`,
`Q ≈ 0.87`) и громкость 0.108 = 0.18 × 0.6 — «ниже и тише» документами не оцифровано, это
наше решение. Огибающая: старт с громкости и `exponentialRampToValueAtTime(0.0001, now+0.06)`;
ровно `0` в WebAudio нельзя — исключение. Буфер — 60 мс белого шума, создаётся один раз.

**R4. Состояние звука.** `localStorage['book.sound.v1']` = `'on'`/`'off'`. Если ключа нет —
звук включён, кроме `prefers-reduced-motion: reduce` (тогда выключен по умолчанию,
ESENIN:182). Явный выбор читателя главнее умолчания: при сохранённом `'on'` звук работает и
под reduced-motion (`docs/BOOK-READER-PLAN.md:171` — «звук и смена страницы остаются»).
Гейт G4.9 проверяет именно умолчание — на чистом хранилище.

**R5. Ограничитель.** Между стартами звука ≥ 120 мс (`lastPlayedAt`); он же снимает двойной
звук из F4.6. Именно пропуск, а не откладывание: второй звук не играет позже, он не играет
вовсе.

**R6. Контекст — только по жесту.** `new AudioContext` не выполняется при загрузке модуля
ни разу и не выполняется при открытии книги: звук может вообще не понадобиться. Создание —
ленивое, внутри обработчика того жеста, который требует звука: первое листание
(`changeState('flipping')` или `pointerup`) либо включение «Звук» (R11). При
`state === 'suspended'` — `resume()` с `catch`.
Нет конструктора, конструктор бросил или упал сам `playFlip` → `fail(...)`,
`audioBroken = true`, кнопка «Звук» получает `disabled` и `aria-pressed="false"`, книга
листается дальше (ESENIN:173). Сохранённый выбор при отказе НЕ перезаписывается.

**R7. CSS — одна строка.** Нажатое состояние звука красится тем же правилом, что у
переключателей вида (`src/book/book.css:53`): `[data-book] .book-tools
[data-book-sound][aria-pressed="true"] { background: var(--paper-2); }`. Новых цветов,
переходов, `@media print` и анимаций не появляется.

**R8. `site.config.json` не трогаем.** Флага звука в конфиге нет (`site.config.json:46-52`),
§S4 его не требует, файл вне списка шага. Выключатель есть всегда.

**R9. Жизненный цикл звука.** `close()` отпускает звук: `audioCtx.close()` в `try/catch`,
`audioCtx = null`, `noiseBuf = null`, `lastPlayedAt = 0`, слушатели `pointerdown/pointerup`
сняты. Повторное открытие создаёт контекст заново по жесту. Слушатели StPageFlip снимает
`destroy()` из S3 — не дублируй.

**R10. Упрощённый режим §2.5 закрывается здесь.** S3 требование не взял (состояние выше),
поэтому одна строка в настройках PageFlip: `flippingTime: prefersReduced() ? 0 : 700`;
тени отключаются тем же условием, каким их задал S3 (`drawShadow`/`maxShadowOpacity` —
сверь по S3 T4). Если S3 к моменту работы это уже сделал — не дублируй, отметь в отчёте.
Значение читается при монтировании/remount; слушатель смены медиазапроса в рантайме не нужен.

**R11. Пробный звук при включении не играем.** Иначе счётчики G4 перестают означать «один
звук на листание». Включение только создаёт контекст (жест); звук появится на первом листании.

**T1. Константы (R3, R5).** Рядом с `VIEW_KEY`/`PAGE_PREFIX` (`src/book/book.js:14-15`):
`SOUND_KEY = 'book.sound.v1'`, `SOUND_MS = 60`, `VOLUME = 0.18`, `BACK_VOLUME = 0.108`,
`THROTTLE_MS = 120`, `FWD_BAND = [900, 2600]`, `BACK_BAND = [600, 1800]`. Числа — здесь, в
коде синтеза магических чисел не остаётся.

**T2. Состояние звука (R4).** Модульные переменные: `audioCtx = null`, `noiseBuf = null`,
`lastPlayedAt = 0`, `audioBroken = false`, `soundOn = false`. Функции: `prefersReduced()`
(`window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches`, с
защитой от отсутствия `matchMedia`), `readSoundPref()` (ключ → `'on'`/`'off'` → иначе
`!prefersReduced()`), `writeSoundPref(on)` (`'on'`/`'off'`). Инициализация `soundOn` — при
открытии книги (T8), не при импорте модуля.

**T3. Синтез и воспроизведение (R3, R5, R6).** Четыре функции, каждая с обработкой ошибок
через `fail(...)`:

- `ensureAudio()` — ленивое создание `new (window.AudioContext || window.webkitAudioContext)()`,
  при `state === 'suspended'` — `ctx.resume().catch(...)`; нет конструктора или бросил —
  `settleAudioError(err)`;
- `noiseBuffer(ctx)` — один раз на контекст: буфер `ctx.sampleRate * 0.06` сэмплов, моно,
  заполнен `Math.random()*2-1`, кеш в `noiseBuf`;
- `playFlip(dir)` — порядок проверок: `soundOn`, `!audioBroken`, `state`, затем
  `performance.now() - lastPlayedAt < THROTTLE_MS` → выход без звука (R5). Дальше:
  `ensureAudio()` → `createBufferSource` (`noiseBuffer`), `createBiquadFilter` (`type='bandpass'`,
  `frequency.value = f0`, `Q.value = f0/полоса`), `createGain`
  (`gain.value = (dir === 1 ? VOLUME : BACK_VOLUME)`, затем
  `exponentialRampToValueAtTime(0.0001, now + 0.06)`), сборка
  `source → filter → gain → destination`, `source.start()`, `lastPlayedAt = now`. Ошибка на
  любом шаге — `settleAudioError(err)`, без исключения наружу.
- `settleAudioError(err)` — `fail('звук недоступен', err)` один раз, `audioBroken = true`,
  кнопка «Звук»: `disabled`, `aria-pressed="false"`, `title` с причиной; сохранённый выбор не
  перезаписывается (R6).

**T4. Точки запуска (R1, R2).** В блоке подписок StPageFlip, который создал S3:

1. `pageFlip.on('changeState', (e) => { if (e && e.data === 'flipping') playFlip(nextDir()); })` —
   кнопки, клик по странице, угол. На `flip` подписку для звука не добавлять.
2. Перетаскивание: `pointerdown` на `state.stage` в фазе перехвата запоминает `clientX` и
   сбрасывает флаг движения; `pointermove` (фаза перехвата, `passive`) ставит флаг, если
   смещение по X больше 5 px; `pointerup` на сцене в фазе перехвата при поднятом флаге делает
   `playFlip(dx < 0 ? 1 : -1)` и гасит флаг. Перехват на сцене приходит раньше `userStop`
   библиотеки (F4.7) — звук встаёт в начало анимации.
3. `nextDir()` реализует приоритет R2: `pendingDir` → `pendingDir = 0`; иначе знак `dx`
   (перетаскивание); иначе половина сцены по `pointerdown` (правая — вперёд); иначе вперёд.
   `pendingDir` ставят обработчики «‹/›» **перед** вызовом `flipPrev()`/`flipNext()`.
4. `pointerdown`/`pointerup` снимаются в `close()` (T8); подписка `changeState` живёт на
   объекте PageFlip и умирает вместе с `destroy()`.

**T5. Выключатель «Звук» в тулбаре (R4, R7, R11).** В `buildSection` — кнопка по образцу
`prev`/`next` (`src/book/book.js:186-199`): `data-book-sound`, текст «Звук»,
`aria-pressed = String(soundOn)`. Вставляется в `bar.append(...)` (`:200`) между `btnSpread` и
`prev`. Клик: `soundOn = !soundOn`, `writeSoundPref(soundOn)`, обновить `aria-pressed`, при
включении — `ensureAudio()` (жест), пробного звука нет (R11). Начальное значение — T2;
если `audioBroken` уже взведён, кнопка сразу `disabled`. CSS — R7 (`src/book/book.css`, одна
строка после `:53`).

**T6. Отказ WebAudio (R6).** Проверяется не «глазами», а сценарием G4.10: конструктор
отсутствует или бросает — книга открывается, листается, звука нет, `console.warn` есть,
исключений нет, кнопка `disabled`. Никакого отката в обычный текст из-за звука: звук —
необязательное улучшение (ESENIN:173).

**T7. Упрощённый режим §2.5 (R10).** В настройках PageFlip (S3 T4, строка `flippingTime: 700`):
`flippingTime: prefersReduced() ? 0 : 700`; тени — тем же условием, каким их задал S3. Если
S3 уже сделал эту ветку — не дублируй, отметь в отчёте. Ничего не пересобирать на живой
смене медиазапроса.

**T8. Жизненный цикл (R9).** В `open()`: `soundOn = readSoundPref()`, состояние кнопки — по
нему; слушатели `pointerdown`/`pointermove`/`pointerup` — на `state.stage`. В `close()`:
снять эти три слушателя, `if (audioCtx) try { audioCtx.close(); } catch (err) { fail(...); }`,
обнулить `audioCtx`, `noiseBuf`, `lastPlayedAt`, `pendingDir`; `audioBroken` и `soundOn`
вернуть к умолчаниям — следующее открытие читает ключ заново.

**T9. Инструментальный стенд (G4).** `scratch/s4-audio.mjs` — headless Chrome по CDP, образец
стенда — G5 постановки S3 (`node scripts/serve.mjs` на `localhost:4173`, percent-encoded URL
«Бобыль и Дружок», клик по `data-book-open`). Обязательные свойства стенда:

- инструментация ставится **до** первой навигации (`Page.addScriptToEvaluateOnNewDocument`):
  счётчик конструкторов `AudioContext`, запись созданных `AudioBuffer` (`createBuffer`),
  `AudioBufferSourceNode.prototype.start` с `performance.now()`, созданных
  `BiquadFilterNode`/`GainNode` (частота, `Q`, `gain.value` на момент `start()` — читать
  синхронно внутри патча `start`, иначе увидишь уже спавшую огибающую);
- клики и перетаскивание — CDP `Input.dispatchMouseEvent` (реальный жест), а не
  `element.click()` из `Runtime.evaluate`: у последнего нет user activation;
- Chrome запускается с `--mute-audio`; если контекст остаётся `suspended`, стенд
  перезапускается с `--autoplay-policy=no-user-gesture-required` (флаг стенда, в приложении
  его нет) и факт фиксируется в отчёте;
- в конце — сводка: число `start()`, интервалы между ними, частоты, `Q`, громкости, RMS
  буфера, `EXIT` стенда.

**T10. Замер и отчёт.** `wc -c src/book/book.js src/book/book.css` → прирост к 18 258 (F9);
`git ls-files | grep -Ei '\.(mp3|wav|ogg|m4a)$' | wc -l` → 0; `grep -rn "<audio\|new Audio("
src/ | wc -l` → 0. Отчёт — по §6.

## Вопросы

**В1. Кто подтверждает звук на слух?**
Исполнитель — агент на Windows без слуха: G4 доказывает существование сигнала, его частоту,
громкость, момент старта и глушение, но не «похоже на шелест бумаги». Вариант A (принят по
умолчанию): шаг закрывается по G4, тембр слушает владелец на приёмке (S7) — цена: неудачный
тембр всплывёт позже и правится одной строкой чисел R3, зато шаг не стоит. Вариант B: шаг
держится открытым до прослушивания владельцем — цена: S4, S5 и S6 не начинаются, пока
владелец не сядет за машину. Молчаливая подмена («звук есть, значит слышно») запрещена: в
отчёте строка «на слух не проверено».

**В2. Как считается бюджет 20 КБ?**
Сейчас `book.js` + `book.css` = 18 258 байт (F9); S3 добавит нарезку и монтирование, звук —
свой прирост, и 20 КБ (= 20 480 байт по конвенции S3 F10) могут не сойтись. Вариант A
(принят по умолчанию): S4 только меряет и докладывает числа, порог и его приведение в
`verify.mjs` — дело S6, где гейт и реализуется; если бюджет не сходится, S6 решает, что
ужимать. Вариант B: порог 20 000 байт и требование уложиться уже в S4 — цена: правка чужого
кода S2/S3 внутри шага звука и риск регресса нарезки текста.

## Ревью (обязательно)

Шаг закрывает не исполнитель. После кода и зелёных гейтов работа уходит на независимое ревью
роли `reviewer` (скилл `pipeline-reviewer`): он читает план §S4 (`docs/plans/1-book-reader.md:89-94`),
`docs/BOOK-READER-ESENIN-PLAN.md` §7 и §8 п.3, `docs/BOOK-READER-PLAN.md` §2.5 и фазу 4, и
код — а не отчёт исполнителя: отчёт источником фактов не считается.

- Вердикт: **APPROVE** или **REQUEST_CHANGES**, третьего нет.
- При REQUEST_CHANGES шаг остаётся открытым: находки правятся в тех же двух файлах, гейты
  G0-G5 прогоняются заново, ревью повторяется.
- Строка «ЗАКРЫТ» в журнале плана и коммит закрытия — только после APPROVE, их делает страж
