## Роль и цель

Ты — программист сайта о Есенине. Задача: подключить к книжному виду вендоренную
библиотеку StPageFlip (`page-flip` 2.0.7, MIT) и сделать настоящее перелистывание листом
с изгибом — мышью, пальцем и кнопками «‹»/«›»; разворот и одна страница переключаются
по ширине сцены. Книга по-прежнему инициализируется из `.poem[data-book-source]`,
позиция чтения не теряется, при отказе библиотеки читатель остаётся на обычном тексте.
Звука, клавиатуры кроме Esc, `aria-live`, печати, метрики и подстановочных гейтов в этом
шаге нет — это S4-S6.

### Решения, принятые постановкой (менять нельзя, оспаривать — вопросом)

**R1. Разбиение книжных гейтов §8 между S3 и S6.** §S3 требует зелёных гейтов «файл в
`dist/book/`, размер ≤ 50 КБ, заголовок MIT, отсутствие canvas в HTML» и включает
`scripts/verify.mjs` в файлы шага, а S2 правки `verify.mjs` запрещает. Решение: S3
добавляет в книжный блок четыре проверки — (а) наличие `dist/book/book.js`,
`dist/book/book.css`, `dist/book/stpageflip.js`; (б) MIT-шапка и `StPageFlip` в первых
2 КБ `stpageflip.js`; (в) `stpageflip.js` ≤ 51 200 байт; (г) ни в одном собранном HTML нет
элементов canvas. Остальные пункты §8 (бюджет `book.js`+`book.css` ≤ 20 КБ, «ровно 17»,
сумма текста по `works.json`, `book.js` не в HTML, кнопка 17/0/0) и подстановочные
прогоны — S6, он же доберёт недостающее. Правки существующих проверок V1-V6 запрещены.

**R2. Заголовок MIT добавляем к вендоренному файлу.** Сырой бандл лицензионной строки не
содержит (F4), гейт §8 п.2 без неё непроходим. Решение: `src/book/stpageflip.js` = шапка
комментария (MIT-текст из `LICENSE` пакета, упоминание `StPageFlip`, версия 2.0.7, ссылка
`https://github.com/Nodlik/StPageFlip`) + тело бандла без изменений. Проверка целостности
тела: `tail -c 44058 src/book/stpageflip.js | sha256sum` совпадает с хешем из F4.
Правка тела бандла запрещена — это стоп-сигнал S6.

**R3. Вид задаёт ширина сцены, а не API ориентации.** Ширину сцены в одиночном и
разворотном режиме по-прежнему задаёт CSS постановки S2 (T6); библиотека сама выбирает
`landscape`/`portrait` по ширине родителя (README: `usePortrait`; прототип F7).
Принудительно переключать ориентацию через API запрещено — только слушать
`changeOrientation` для синхронизации счётчика и состояния кнопок.

**R4. Кнопки «‹»/«›» остаются на месте, но получают анимацию.** В S2 они сдвигали поток
мгновенно; в S3 они вызывают `flipPrev()`/`flipNext()` (один лист за нажатие), счётчик и
`disabled` обновляются на событии `flip` через `getCurrentPageIndex()` (в развороте индекс
выровнен по паре — F7). Номер, который видит читатель, — см. вопрос В2.

**R5. Нарезка и обложка.** Страницы режутся по `Range` с округлением границ вниз
(`docs/BOOK-READER-PLAN.md`, фаза 3); первая и последняя страница — `data-density="hard"`.
Сумма текста всех нарезанных страниц обязана совпасть с текстом источника — это контракт
шага, проверяется (не в `verify.mjs`, а) headless-скриптом из `scratch/` по образцу G4
постановки S2; вывод идёт в отчёт.

**R6. `scripts/build.mjs`, скорее всего, не потребует правок.** Копирование всех файлов
`src/book` в `dist/book` и включение их в `data-v` уже заложены задачами T2/T3 постановки
S2. Проверь фактом после S2: `grep -n "src/book" scripts/build.mjs` — если копирование на
месте, в S3 файл не трогай. Правка `build.mjs` допустима только с обоснованием в отчёте.

**R7. Проверочные скрипты — только в `scratch/`.** `scratch/` в `.gitignore`; в отчёт
выводится результат, сам скрипт — в коммит не входит.

**R8. npm-зависимостей нет.** Библиотека качается `curl` во временный файл (`$TMPDIR`) и
кладётся в `src/book/`; `package.json` не изменяется, `npm install` не запускается.

**R9. `maxShadowOpacity` = 0,5 — решение постановки, не цитата документа.** Ни §4, ни
`docs/BOOK-READER-PLAN.md:207` числа не задают (там параметр назван без значения). Берём 0,5:
тень при изгибе заметна, но текст страницы не темнеет. Значение попадает в код константой,
менять его без нового решения нельзя; проверка — глазами в G6 (страница при перетаскивании
не «сереет»).

(`src/book/book.css:76-97`): `--book-size`, `text-align: justify`, `hyphens`, стили
`.book-part`, `.book-date`, `.book-head`, `.book-verse`. S2 строит контейнер один раз и
наполняет клонами (`src/book/book.js:205-212`); после нарезки по `Range` в элементы `.page`
колонки-контейнера больше нет, и правила остаются без носителя. Перенеси правила на
элементы страниц: кегль и `--book-size` (на `.page`), выключка и переносы (на содержимое
страницы), `.book-part`/`.book-date`/`.book-head`/`.book-verse` (на сами элементы внутри
страницы). Оригинал `.poem` не трогается; стили S2 не удаляются — они продолжают работать
для обычного вида. Проверка — глазами в G6: части, даты и стихотворные цитаты выглядят как
в S2.

**T5. Кнопки и вид.** «‹»/«›» из тулбара S2 → `flipPrev()`/`flipNext()` (R4), при
`pageCount = 1` — `disabled` (контракт S2, §5). Ширина сцены — CSS S2, переключатели
«Одна страница»/«Разворот» продолжают менять ширину сцены, ориентацию выбирает
библиотека (R3). `Esc` и кнопка «Обычный текст» работают как в S2.

**T6. Позиция и remount по resize.** Доля из `localStorage` (ключ `book.page.` + slug +
`.v1`, 4 знака) применяется при готовности книги: `getCurrentPageIndex()` → `turnToPage()`
без анимации. Единственный триггер пересборки в этом шаге — `resize` (включая смену
ориентации окна): `destroy()` → пересборка страниц → новая загрузка → возврат на ту же
долю. Позиция после ресайза обязана совпасть до ±1 листа (G5.4, ручной G6). Управления
кеглем в книге пока нет (тулбар S2 — выход, вид, «‹», счётчик, «›»; `.poem-tools` в книге
скрыты, `src/book/book.css:14`), поэтому ветки «на изменение шрифта» здесь нет: remount по
кеглю появится в шаге, который этот кегль вводит.

**T7. Откат (контракт шага).** Если библиотека не загрузилась или `window.St.PageFlip`
не появился: обычный текст S2 (те же `.poem[data-book-source]`), сообщение через
`console.warn`, книжная сцена не рисуется, пустого экрана нет. Атрибуты и ключи из F9 не
меняются. Откат не декларируется, а проверяется исполняемо — пункт G5.5.

**T8. Книжные гейты в `verify.mjs` (R1).** После `scripts/verify.mjs:482`, в том же
стиле: (а) существование трёх файлов `dist/book/*`; (б) в первых 2 КБ
`dist/book/stpageflip.js` есть `MIT` и `StPageFlip`; (в) размер
`dist/book/stpageflip.js` ≤ 51 200 байт; (г) ни в одном HTML из `dist/` нет элементов
`canvas` (проверка по всем `*.html`, а не по одному файлу). Ошибки — `errors.push(...)` с
адресом файла, стиль и язык — как у V1-V6. Существующие V1-V6 и
`info.push('book: …')` не трогать.

## Как проверить (гейты)

Оболочка — bash, репозиторий — текущая директория. Каждый прогон: команда, её вывод,
`EXIT` (код возврата именно команды, не хвоста пайпа).

**G0 — baseline, до правок.** `npm run verify > reports/s3-g0.log 2>&1; echo EXIT=$?` →
ожидается `EXIT=0` и строка `ПРОВЕРКА ПРОЙДЕНА: ошибок нет, предупреждений 0` — baseline
обязан быть 0/0. Если предупреждений больше нуля или гейт красный до твоих правок — это
стоп-сигнал S4 (посторонняя причина): записать факт, шаг не начинать. Строку `ПРОВЕРКА …`
из G0 привести в отчёт как есть, а не пересказом.

**G1 — вендоринг (T1).**
`wc -c "$TMPDIR/page-flip.browser.js"` → `44058 page-flip.browser.js`;
`sha256sum "$TMPDIR/page-flip.browser.js"` →
`bbaca0bbef57a22bb66a3fc69d67baf9a17fb9a9c89ec9ed35e2b91abe4bd1e7`;
`tail -c 44058 src/book/stpageflip.js | sha256sum` → тот же хеш (тело не правилось);
`head -c 2048 src/book/stpageflip.js | grep -o "MIT\|StPageFlip" | sort | uniq -c` →
обе строки присутствуют (по `1` или больше).

**G2 — сборка (T2-T5).** `npm run build > reports/s3-build.log 2>&1; echo EXIT=$?` →
`EXIT=0`, в логе строка `book: …`; `ls -l dist/book/` → все три файла:
`book.js`, `book.css`, `stpageflip.js`; `grep -rl "stpageflip" dist --include=*.html | wc -l`
→ `0` (в HTML статического script-тега книги нет, гейт §8 п.7).

**G3 — полный гейт (T8).** `npm run verify > reports/s3-verify.log 2>&1; echo EXIT=$?` →
`EXIT=0` и строка `ПРОВЕРКА ПРОЙДЕНА: ошибок нет, предупреждений 0` — гейт шага `0/0`
(`docs/plans/1-book-reader.md:84`), не «столько же, сколько в baseline». Факты статики
в отчёт: `wc -c dist/book/stpageflip.js` (ожидается ≤ 51 200, ≈ 45 300 с шапкой),
`grep -rn "canvas" dist --include=*.html` → 0 совпадений.

**G4 — подстановка нового гейта (RED, доказательство, что проверка живая).**
`mv dist/book/stpageflip.js dist/book/stpageflip.js.bak && node scripts/verify.mjs; echo EXIT=$?`
→ `EXIT=1` и сообщение об отсутствующем `dist/book/stpageflip.js`;
`mv dist/book/stpageflip.js.bak dist/book/stpageflip.js` (восстановить);
повторно `node scripts/verify.mjs; echo EXIT=$?` → `EXIT=0`. Прогон фиксируется в отчёте.
Подстановки для MIT/размера/canvas делает S6 по §8 (R1) — в этом шаге нужны только
положительные числа G3.

**G5 — нарезка и позиция (headless, scratch).** Скрипт в `scratch/` (R7, образец — G4
постановки S2: поднять `node scripts/serve.mjs` на `localhost:4173`, headless Chrome,
открыть страницу «Бобыль и Дружок» с percent-encoded URL, кликнуть `data-book-open`).
Обязательные строки `PASS` в выводе (и `EXIT=0`):
1. сумма текста всех `.page` равна тексту `.poem[data-book-source]` (сравнение без
   пробельных сжатий — сжатие даёт ложное совпадение);
2. `getPageCount()` равен числу созданных элементов страниц;
3. `flipNext()`/`flipPrev()` меняют `getCurrentPageIndex()` в обе стороны;
4. `turnToPage()` на сохранённую долю после `resize` (например 1280 → 900 → 1280)
   возвращает позицию с точностью до ±1 листа;
5. откат (T7): запрос `/book/stpageflip.js` заблокирован **до** первого клика (CDP
   `Network.setRequestInterception`/`setBlockedURLs`), клик «Режим книги» → `.poem[data-book-source]`
   остаётся видим, элемента `[data-book]` в DOM нет, в консоли поймано `console.warn`,
   пустого экрана нет (высота видимой области с текстом > 0).
Фактические `getPageCount()` для четырёх текстов («Бобыль и Дружок», «У белой воды»,
«Железный Миргород», «Ключи Марии») вывести таблицей рядом с ожиданиями F8.

**G6 — ручной прогон в браузере (контракт §S3; решение владельца В1 = A от 04.11.2026).**
Chrome — исполнителем: открыть «Бобыль и Дружок», клик «Режим книги» — страница
разворачивается листом с изгибом при перетаскивании мышью; кнопки «‹»/«›» листают;
перетаскивание пальцем — если под рукой тач-устройство, иначе отметить «не проверено»;
ширина окна ≥ 1024 — разворот, < 700 — одна страница; resize при открытой книге — позиция
чтения та же; части, даты и стихотворные цитаты выглядят как в обычном виде (T4a); при
перетаскивании листа текст страницы не «сереет» (R9).
Safari в гейт шага не входит (решение A): исполнитель работает на Windows, Safari там нет.
В отчёте Safari фиксируется строкой «не проверено — долг владельца (решение A, 04.11.2026)»;
выдавать его за пройденный запрещено. Прогон делает владелец на macOS до закрытия S6
(пункт в §S6 плана).

## Стоп-сигналы

Останавливайся и докладывай, не «адаптируя по смыслу»:

- **S1.** `src/book/book.js` отсутствует (база S2 не на месте) или журнал плана показывает
  шаг S3 уже «ЗАКРЫТ», а `src/book/stpageflip.js` лежит в дереве — шаг не начинается:
  доложить состояние, закрытую работу не переделывать.
- **S2.** Для зелёного гейта нужна правка файла вне списка шага (`src/styles.css`,
  `src/app.js`, `site.config.json`, `data/*`, `docs/*`, план/журнал, `scripts/serve.mjs`) —
  стоп с точным местом и причиной.
- **S3.** Сумма текста нарезанных страниц не совпала с источником (G5.1) — стоп: границы
  не подгонять, контракт S1 не трогать; доложить позицию и характер расхождения.
- **S4.** `npm run verify` красный по посторонней причине (ссылки, цены, sitemap, журнал,
  аудит текстов): зафиксировать разницу с baseline G0 и не «чинить» чужие проверки.
- **S5.** Тело вендоренного бандла пришлось изменить, чтобы пройти гейт (размер, шапка,
  API) — стоп: вендоринг свят, версию и содержимое менять нельзя (R2).
- **S6.** После загрузки `window.St.PageFlip` не появился или API отличается от F6 — стоп:
  доложить расхождение; версию библиотеки самостоятельно не менять, это решение владельца.
- **S7.** Headless Chrome для G5 недоступен или `serve.mjs` падает на percent-encoded
  URL: перезапустить сервер; дефект `serve.mjs` не чинить, описать в «Расхождениях».
  Инструмент недоступен окончательно — стоп, доложить: G5 обязателен, без него сумма
  текста не доказана.

## Формат отчёта

Отчёт — в карточку шага, на русском, до коммита и без пересказа кода. Порядок разделов:

1. **Что сделано** — по пунктам T0-T8, с адресами (`файл:строка`), одна строка на пункт.
2. **Baseline** — число предупреждений из G0 и строка `ПРОВЕРКА …`.
3. **Вендоринг** — факты G1: размер, оба `sha256` (сырой и хвост файла), результат
   `head -c 2048 | grep`, итоговый `wc -c dist/book/stpageflip.js`.
4. **Сборка** — строка `book:` из G2 и `EXIT`, состав `dist/book`, `EXIT` G3 и число
   ошибок/предупреждений (назвать явно, не «всё зелёное»).
5. **RED-прогон** — вывод G4: сообщение об ошибке, `EXIT=1`, восстановление, повторный
   `EXIT=0`.
6. **Браузер** — вывод G5 целиком: строки `PASS` по пунктам 1-5 и таблица `getPageCount`
   для четырёх текстов против ожиданий F8; ниже — итог G6 по Chrome (что прогнано,
   что «не проверено») и строка по Safari: «не проверено — долг владельца (решение A,
   04.11.2026)».
7. **Расхождения** — минимум: в бандле нет лицензионной строки (шапка добавлена по R2),
   README и бандл называют загрузку страниц по-разному (F6), `build.mjs` не потребовал
   правок либо почему потребовал (R6). Комментарии в коде — по-русски.
8. **Коммит** — только файлы шага: `git add src/book/stpageflip.js src/book/book.js
   src/book/book.css scripts/verify.mjs` (плюс `scripts/build.mjs`, если менялся), затем
   коммит через тот же pathspec: `git commit --` с перечислением этих же путей. Так в коммит не попадут
   файлы, уже лежащие в индексе (F1). Перед пушем: `git show --stat HEAD` — в списке только
   файлы шага; `git push`; полный sha в отчёт. Строка журнала плана НЕ добавляется: её
   пишет страж после APPROVE.

Если гейт не сходится и обойдён быть не может — раздел «Не сделано» с причиной и точным
местом, а не «почти готово».

## Вопросы

**В1. Ручной прогон в Safari — решение владельца от 04.11.2026: вариант A.**
Chrome прогоняется исполнителем. Safari исполнитель запустить не может (Windows), поэтому
в отчёте Safari фиксируется как «не проверено — долг владельца (решение A, 04.11.2026)», а
прогон делает владелец на macOS до закрытия шага S6. G6 и гейт §S3 плана приведены к этому
решению: `docs/plans/1-book-reader.md` — «ручной прогон в Chrome — исполнителем; Safari —
владельцем до закрытия S6», плюс отдельный пункт в §S6. Молча подменять A на B (держать шаг
открытым до Safari) запрещено; если Safari-прогон покажет дефект, он чинится в S6-S7, шаг S3
из-за этого не переоткрывается.

**В2. Какой номер показывает счётчик в развороте?** План не специфицирует. Вариант A
(принят по умолчанию): `getCurrentPageIndex() + 1` — читатель видит номер левого листа
пары (прототип F7: индекс выровнен по паре). Вариант B: номер правого (видимого второго)
листа — `+ 2` в landscape. Цена вариантов: меняется только текст счётчика и шаг
возврата позиции, хранимая доля и порядок листов те же.

## Ревью (обязательно)

Шаг закрывает не исполнитель. После кода и зелёных гейтов работа уходит на независимое
ревью роли `reviewer` (скилл `pipeline-reviewer`): он читает план §S3,
`docs/BOOK-READER-ESENIN-PLAN.md` §3-§6 и §8, `docs/BOOK-READER-PLAN.md` фазу 3 и код, а
не отчёт исполнителя — отчёт источником фактов не считается.

- Вердикт: **APPROVE** или **REQUEST_CHANGES**, третьего нет.
- При REQUEST_CHANGES шаг остаётся открытым: находки правятся в тех же файлах, гейты
  G0-G6 прогоняются заново, ревью повторяется.
- Строка «ЗАКРЫТ» в журнале плана и коммит закрытия — только после APPROVE, их делает
  страж конвейера, не исполнитель.
- Ревьюер обязан проверить отдельно: (1) тело вендоренного бандла не правилось
  (`tail -c 44058 … | sha256sum` = F4), шапка MIT в первых 2 КБ; (2) `package.json` не
  изменён, npm-зависимостей нет; (3) контракт S2 цел — атрибуты и ключи из F9, оригинал
  `div.poem` не тронут, текст книги из клоны; (4) в `verify.mjs` новые проверки стоят
  после :482, V1-V6 не ослаблены, RED-прогон G4 в отчёте; (5) откат T7 доказан пунктом
  G5.5 (заблокированный `/book/stpageflip.js`, обычный текст, `console.warn`, не пустой
  экран), а не только кодом; (6) сумма текста страниц
  доказана выводом G5.1, а не утверждением; (7) коммит содержит только файлы шага
  (`git show --stat`).
