## 1. Роль и цель

Ты — программист шага S5 плана «Книжный режим». S2-S4 сделали кнопку «Режим книги», ленивый запуск, нарезку текста, лист на StPageFlip, тулбар с кнопками (включая «Звук»), счётчиком «N из M» и позицию чтения. Твоя работа — сделать книгу проходимой с клавиатуры и слышимой для скринридеров: ←/→, Home/End, Space, Esc, видимый и не теряющийся фокус, `role="region"` c `aria-roledescription`, живой регион «Страница N из M» и возврат фокуса на кнопку при выходе. NVDA ты не запускаешь и не выдаёшь за запущенный (В1).

Контракт шага из §S5 (`docs/plans/1-book-reader.md:99-103`):

- **C1.** Работают ←/→, Home/End, Space; Esc и «Обычный текст» выходят из книги.
- **C2.** `role="region"`, `aria-roledescription="книга"`, `aria-live` с номером страницы (текст «Страница N из M»).
- **C3.** Фокус не теряется при перелистывании; страница проходится без мыши целиком — `Tab`, `←/→`, `Home/End`, `Space`, `Esc` (проверки T6.1-T6.8 и ручной прогон G6).
- **C4.** «Важно»: номера страниц в вёрстке помечены `aria-hidden`, чтобы не читались дважды (трактовка — R6, вопрос В2).
- **C5.** `npm run verify` не красный (0 ошибок; предупреждения — по R9), ручной прогон клавиатурой на «Железном Миргороде», анонс доказан инструментально (NVDA — В1).
- **C6.** Постановка в `docs/prompts/` прошла `check_task_prompt.py` (проверено постановщиком, перепроверяется в G5).

## 4. Решения (приняты постановкой; менять нельзя, оспаривать — вопросом владельцу)

- **R1. Фокус.** При открытии — программно на секцию: `state.section.focus({ preventScroll: true })` после прокрутки к месту чтения (`book.js:778`). При закрытии (обе ветки выхода идут через `close()`: Esc и «Обычный текст») — на `.poem-tools [data-poem-action="book"]`, но только если элемент `isConnected`; иначе `document.activeElement` возвращать не нужно. Куда вернуть, `close()` запоминает из модульной переменной `returnFocus`, которую `open()` пишет **до** первого `await`.
- **R2. Home/End — `turnToPage`.** `goto(index)` рядом с `turn()`: `s.flip.turnToPage(…)` с зажатием в границы `[0, pageCount - 1]`, затем явные `sync()` и `savePosition()`; без анимации, ровно как восстановление позиции при открытии (`book.js:596-601`, `flip.on('init', …)` → `turnToPage` `:599`). Ожидание Home: индекс `0` и счётчик «1 из N». Ожидание End: в `portrait` индекс `N - 1`; в `landscape` — по формуле самой `sync()` (`index >= total - step`, «›» при этом `disabled`), потому что в развороте счётчик показывает левую страницу пары (вопрос В2 постановки S2, комментарий `book.js:403`).
- **R3. Объявление — только при изменении.** Текст живого региона ровно `'Страница ' + (Math.min(index, Math.max(total - 1, 0)) + 1) + ' из ' + total` (те же числа, что в счётчике `:411`); присваивание — под `if (текст отличается)`. Иначе remount при ресайзе или смене вида повторно объявил бы ту же страницу, а это шум для скринридера.
- **R4. Space с охраной интерактивных целей.** `preventDefault()` + `turn(1)`, только если `event.target` не попадает в `button, a[href], summary, [role="button"], input, textarea, select, [contenteditable="true"]`. Для этих целей работает нативное срабатывание/ввод, и перехват дал бы двойное действие (нажатие «Обычный текст» не должно листать книгу).
- **R5. `class="book"` не добавляем** (D6): селекторы проекта — `[data-book]`, контракт S2/S3 не расширяется ради цитаты документа.
- **R6. «Номера страниц» = счётчик тулбара.** `aria-hidden="true"` получает `[data-book-counter]`, чтобы номер читал только живой регион и не было двойного чтения. Номера «стр. N» под листами в этом шаге **не добавляются**: их нет ни в «Готово =», ни в дереве, а появление текста в листах сломает сверку суммы текста (план S3:85, общий план §5 п.1:337-339). Спор по этому пункту — В2.
- **R7. NVDA — владельцу, инструмент — стенд.** Главное доказательство C2 — стенд (F-проверка живого региона, фокуса и клавиш): заголовок шага «скринридер объявляет» исполняется как `aria-live`, который меняет текст. Аудиопрослушивание NVDA агент не выдаёт за пройденное: в отчёте строка «NVDA не установлен, прогон владельца — В1».
- **R8. Объём шага.** Только клавиатура, фокус, `role`/`aria-roledescription`/`aria-label`, живой регион, `aria-hidden` счётчика и фокус-стили. Не входит: прогресс-полоса (§2.4), номера под листами (В2), A−/A+, «К началу», «Распечатать» (S6), `PageUp`/`PageDown`, переход по номеру, скрытие соседних листов от скринридера, звук (S4), печать и гейты `verify.mjs` (S6), Safari (решение A от 04.11.2026).
- **R9. Verify: ноль ошибок обязателен, предупреждения — по факту baseline.** Допустимо ровно то предупреждение, что было в G0 (по F12 — «очередь журнала»). Новая ошибка или новое предупреждение = стоп S2: чужие проверки не правятся.
- **R10. Клавиатурный обработчик книги — в capture-фазе.** В `openInternal` подписка становится `document.addEventListener('keydown', onKeydown, true)` (`book.js:755`), в `close()` — `document.removeEventListener('keydown', onKeydown, true)` (`:814`): третий аргумент при снятии обязан совпадать с флагом при подписке, иначе обработчик остаётся на `document` после закрытия книги. Причина — F9: `app.js` подписан раньше и в bubble-фазе снимает атрибут `open` до нас, поэтому охрана «открыт диалог» в T4 обязана срабатывать в capture-фазе и искать фактический элемент — `document.querySelector('[data-search-dialog][open]')`; селектор `dialog[open]` не совпадает ни с чем (тега `dialog` в дереве нет, F9). Второй охраны вида `event.target.closest('[data-search-dialog]')` не добавлять: при закрытом диалоге она глушила бы Escape для книги.

Вспомогательный переход (R2):

```js
function goto(index) {
  const s = state;
  if (!s || !s.flip) return;
  try {
    const total = s.flip.getPageCount();
    s.flip.turnToPage(Math.max(0, Math.min(total - 1, index)));
    sync();
    savePosition();
  } catch (err) {
    fail('переход по клавише не удался', err);
  }
}
```

Обработчик целиком (порядок охран важен: сначала всё, что чужое, потом наши клавиши):

```js
function onKeydown(event) {
  // 1. Комбинации не наши: Ctrl/Cmd+K и т.п. живут в src/app.js:119-146.
  if (event.ctrlKey || event.metaKey || event.altKey) return;
  // 2. Открыт диалог поиска: его Esc/стрелки ведёт app.js, книга не мешает.
  //    Диалог — div в футере с атрибутом open (F9), а не тег dialog: тега dialog
  //    в дереве нет, поэтому селектор 'dialog[open]' не совпал бы ни с чем.
  //    Охрана имеет смысл только в capture-фазе (R10): подписка ниже — с третьим
  //    аргументом true, иначе app.js успевает снять open (F9).
  if (document.querySelector('[data-search-dialog][open]')) return;
  const t = event.target instanceof Element ? event.target : null;
  // 3. Ввод текста: стрелки двигают курсор, Space печатает пробел.
  if (t && t.closest('input, textarea, select, [contenteditable="true"]')) return;
  if (event.key === 'Escape') { close(); return; }
  const s = state;
  if (!s || !s.flip) return;
  const interactive = t && t.closest('button, a[href], summary, [role="button"]');
  if (event.code === 'Space' || event.key === ' ') {
    if (interactive) return;          // R4: работает нативное срабатывание кнопки
    event.preventDefault();           // Space не прокручивает страницу
    turn(1);
    return;
  }
  if (event.key === 'ArrowRight') { event.preventDefault(); turn(1); return; }
  if (event.key === 'ArrowLeft')  { event.preventDefault(); turn(-1); return; }
  if (event.key === 'Home')       { event.preventDefault(); goto(0); return; }
  if (event.key === 'End')        { event.preventDefault(); goto(s.flip.getPageCount() - 1); return; }
}
```

Подписка и снятие (R10): в `openInternal` строка `document.addEventListener('keydown', onKeydown)` (`:755`) получает третий аргумент `true`; в `close()` строка `document.removeEventListener('keydown', onKeydown)` (`:814`) — тоже `true` (флаг обязан совпасть, иначе обработчик останется на `document` после закрытия). Без этого охрана №2 в bubble-фазе не работает: `app.js` подписан раньше (F9) и уже снял атрибут `open` у `[data-search-dialog]`, поэтому Escape при фокусе на `✕` диалога закрывал бы книгу вместе с диалогом — жёсткий случай проверяет T6.9.

## 10. Вопросы

**В1. Кто и когда слушает NVDA?**
Принят вариант **A**: шаг доказывается стендом (живой регион меняет текст на «Страница N из M», фокус и клавиши — G4/G6), а NVDA-прогон приёмкой — долг владельца, как «на слух» для звука в постановке S4 и Safari для S3. Цена: если NVDA прочитает иначе (например, даст лишнее объявление при ресайзе), это вскроется после закрытия шага и уйдёт в отдельную задачу. Вариант B — дождаться установленного NVDA: цена — шаг встанет надолго, `where nvda` пусто, ставить скринридер исполнитель не может.

**В2. Нужны ли номера «стр. N» под каждым листом?**
Принят вариант **A** (текущее решение R6): в этом шаге номера не добавляются, `aria-hidden` получает счётчик тулбара, требование общего плана §2.4 «под каждой страницей `стр. 12`» остаётся невыполненным и записывается в долги шага. Цена: расхождение с документом доживёт до S7 или отдельной задачи, в развороте читатель видит только счётчик. Вариант B — добавить номер элементом `aria-hidden` в каждый лист: цена — правка сверки суммы текста (план S3:85 и §5 п.1 поймают лишние символы), то есть риск ради косметики в чужом гейте; такое решение должно прийти явно.

## 11. Ревью (обязательно)

Шаг закрывает не исполнитель, а роль `reviewer` по скиллу `pipeline-reviewer`: после кода и гейтов карточка уходит на независимое ревью с вердиктом **APPROVE** или **REQUEST_CHANGES**.

- Источники ревьюера: §S5 плана (`docs/plans/1-book-reader.md:97-104`), `docs/BOOK-READER-PLAN.md` §2.4/§2.6/фаза 5, `docs/BOOK-READER-ESENIN-PLAN.md` §7/§8 п.5, код на коммите исполнителя и собственный прогон его гейтов. Отчёт исполнителя источником фактов не является.
- Чек-лист для ревьюера: 1) работают ←/→, Home/End, Space, Esc и видят охраны T4 (диалог — по фактическому элементу `[data-search-dialog][open]`, а не `dialog[open]`: тега `dialog` в дереве нет, F9; ввод, модификаторы), подписка `keydown` и её снятие — в capture-фазе с одинаковым флагом `true` (R10, F9: иначе Escape при фокусе на `✕` диалога закрывает книгу вместе с ним); 2) `role="region"` + `aria-roledescription="книга"` + `aria-label` с числом страниц, живой регион `aria-live="polite"` с текстом «Страница N из M» и обновляется только при изменении; 3) `aria-hidden` на счётчике и нигде больше — на сцене, потоке и листах ни одного; 4) фокус: вход на секцию при открытии, возврат на «Режим книги» при Esc и при «Обычный текст», ободок по `:focus-visible`, фокус не теряется при перелистывании и ресайзе; 5) `ИТОГ: 12 PASS, 0 FAIL`, `npm run verify` — 0 ошибок и предупреждения без новых относительно G0, `grep -l "book\.js" dist/works/*.html | wc -l` → 0 — перепроверены командами; 6) чужие файлы не тронуты и код S4 на месте (`grep -c "SOUND_KEY" src/book/book.js` → 4, `btnSound` остался в `bar.append` и `return`), `git show --stat` показывает только два файла книги; 7) план и журнал не изменены; 8) отчёт не выдаёт стенд за NVDA-прогон.
- **APPROVE** — шаг закрыт стражем (строка журнала «ЗАКРЫТ» с sha и доказательствами; её не пишет ни исполнитель, ни ревьюер). **REQUEST_CHANGES** — шаг остаётся открытым: находки правятся, ревью повторяется, до APPROVE «ЗАКРЫТ» не появляется. Ревьюер не правит код и не досматривает работу за исполнителя.

Вопросы, которые подняты здесь (В1, В2), не останавливают работу: исполнитель идёт по принятым вариантам A и докладывает в разделе «Расхождения», владелец может переопределить уже после.
