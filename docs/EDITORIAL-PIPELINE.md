# Редакционный конвейер журнала

Правило проекта: **одна публикация в будний день, и в запасе всегда готовые статьи на две недели
вперёд** (14 будних дней). Ни одна статья не попадает в очередь без ревизии агента-филолога.

Документ описывает, кто что делает, что считается «готовой статьёй» и как контролируется запас.
Действует в обоих проектах серии (`bunin-site`, `esenin-dashboard`).

## 1. Что считается готовой статьёй

Файл `content/publications/<slug>.md` с будущей датой готов, если выполнено всё:

1. **Дата** — ближайший свободный будний день, `date: YYYY-MM-DD` в шапке; даты в очереди
   не пересекаются.
2. **Объём** — от 2 500 знаков (жёсткий гейт `text-audit`), практически 5 000–9 000.
3. **Источники** — поле `sources` с конкретным изданием: том, журнал с номером и годом,
   мемуары с названием и годом. «По материалам интернета» не принимается.
4. **Иллюстрация** — файл в `public/img/journal/`, свободная лицензия, подпись, автор
   и ссылка на страницу файла на Викискладе; картинка уникальна в журнале и статьях.
5. **Ссылки внутрь сайта** — 2–3 живые ссылки (произведение, персона, место, раздел).
6. **Ревизия филолога** — отчёт получен, обязательные правки внесены, вердикт «можно выпускать».
7. **Гейты** — `npm run verify` даёт 0 ошибок; предупреждения по статье разобраны.

## 2. Роли и порядок

| Шаг | Кто | Что на выходе |
|---|---|---|
| 1. Тема | календарь (`docs/POOL-TOPICS.md`) | заголовок, тезис, источники |
| 2. Черновик | автор | файл статьи с датой, картинкой, ссылками |
| 3. Ревизия | **агент-филолог** | список правок: «цитата → замена → источник» + вердикт |
| 4. Правки | автор | статья с внесёнными исправлениями |
| 5. Проверка | `npm run verify` | 0 ошибок, предупреждения разобраны |
| 6. Коммит | автор | статья уходит в репозиторий с будущей датой |
| 7. Выход | ежедневный крон 06:30 МСК | статья с датой «сегодня» появляется на сайте сама |

Порядок не переставляется: **публикация без ревизии невозможна**, даже если текст кажется
безопасным. Филолог проверяет даты и стиль (старый/новый), атрибуции цитат, числа, названия
изданий, тон и объём.

## 3. Контроль запаса

- `npm run queue:status` — сколько вышло, сколько в запасе, на сколько будних дней вперёд,
  есть ли дыры в календаре.
- `verify` предупреждает, если запас меньше 14 будних дней или очередь пуста. Это предупреждение,
  а не ошибка: срочная правка сайта не должна блокироваться из-за редакционного долга.
- Запас поддерживается партиями: пишем 3–4 статьи за сессию, пока впереди не станет 14+ дней.

## 4. Чего не делаем

- Не двигаем даты задним числом, чтобы «закрыть» пропуск: если день пропущен, статья встаёт
  на ближайший свободный будний день, а в календаре остаётся видимая дыра.
- Не публикуем черновик «потом поправим»: дата в прошлом означает, что крон выложит его
  на следующей сборке.
- Не ставим в очередь статью без иллюстрации: изображение проверяется тем же гейтом, что и текст.
- Не переиспользуем одну картинку в двух статьях — `verify` это ловит.

## 5. Если филолог нашёл ошибку в уже вышедшей статье

1. Правка вносится в файл независимо от даты (у вышедшей статьи дата не меняется).
2. Коммит с обычным сообщением, в котором указано, что именно исправлено.
3. Ближайшая сборка обновляет страницу; в подвале меняется «Обновлено».
4. Если ошибка повторяется в других статьях — правится класс ошибок во всех сразу
   (правило серии).
