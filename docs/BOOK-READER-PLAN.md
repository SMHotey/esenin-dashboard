# Книжный виджет в библиотеке: план реализации

Задача: при открытии рассказа показывать текст не как веб-страницу, а как печатную книгу —
с постраничной разбивкой, перелистыванием и звуком, номерами страниц, нормальной вёрсткой
(выключка, переносы, абзацный отступ) и переключателем «разворот / одна страница».

Документ фиксирует решения, порядок работ, приёмочные критерии и риски. Реализация — отдельными
коммитами по фазам, каждая фаза заканчивается зелёным `npm run verify`.

**Виджет не включён по умолчанию.** По умолчанию страница произведения остаётся такой, как
сейчас: обычный текст с прокруткой. Режим книги — выбор читателя: кнопка «Режим книги» в тулбаре,
выбор запоминается на устройстве, есть возврат «Обычный текст». Скрипт книги при этом не грузится
до первого включения — вес страницы, скорость и SEO остаются прежними.

Дата: 01.11.2026. Проект: `bunin-site` (36 рассказов, 3,6–65 тысяч знаков). После приёмки —
перенос в `esenin-dashboard` (правило серии).

## 1. Что уже есть и на что опираемся

- Тексты лежат в `data/works.json` как чистый текст с абзацами через пустую строку; HTML внутри нет.
- На странице произведение выводится одним блоком: `<div class="poem">` + `white-space: pre-wrap`
  (стихи держатся только на этой разметке). Для книги этого мало: нужны настоящие `<p>`, иначе
  абзацный отступ и переносы не работают, — значит, для прозы при сборке текст разбивается
  на абзацы по пустой строке.
- Страница произведения собирается в `scripts/build.mjs` (`workPage()`): заголовок, тулбар
  (`data-poem-action`: шрифт, режим чтения, без оформления, печать, копирование), текст, источник.
- Вся интерактивность — ванильный `src/app.js` (16 КБ, без библиотек), стили — `src/styles.css`.
- Есть страница «для печати» (`/print/`) и печатные стили.
- Сайт статический, деплой на GitHub Pages, `npm run verify` — жёсткий гейт.

Отсюда два ограничения, которые определяют всю архитектуру: **никаких внешних библиотек**
(перелистывалки типа turn.js весят 30–60 КБ, ломают доступность и требуют jQuery) и **текст обязан
остаться в HTML** — иначе страницы выпадают из поиска.

## 1а. Что уже проверено прототипом

Собран одноразовый вариант (не в репозитории): «Господин из Сан-Франциско» разбит на 53 абзаца
по `<p>`, обёрнут в колонки `column-width: 480px`, сцена 1100×700, `column-fill: auto`,
выключка, переносы, абзацный отступ. Замер в Chromium:

| Показатель | Значение |
|---|---|
| знаков в тексте | 43 267 |
| слов | 6 580 |
| колонок (страниц) при 480×700 | 46 |
| ёмкость страницы | ≈940 знаков |
| `scrollWidth` при 46 колонках | 25 000 px (46 × (480 + 60) = 24 840) |

Выводы, которые план уже учитывает:

- техника работает и даёт правдоподобную книжную ёмкость (~940 знаков на страницу — это примерно
  как в массовом издании 84×108/32);
- `Math.round` вместо `Math.ceil`: разница 160 px в хвосте `scrollWidth` — это округление
  дробной ширины колонки, и `ceil` дал бы 47-ю пустую страницу;
- оценка объёма книги для остальных рассказов: `страниц ≈ знаков / 940` (медианный рассказ
  14 тыс. знаков — ≈15 страниц, самый короткий 3,6 тыс. — 4 страницы);
- проверен только Chromium: Safari и Firefox остаются в матрице QA (фаза 6), потому что именно они
  расходятся в подсчёте `scrollWidth` и в распределении `column-fill`.

## 2. Ключевые решения

### 2.1. Разбивка на страницы — во время чтения, а не при сборке

Печатная книга имеет фиксированный формат, браузер — нет: ширина окна, размер шрифта и настройка
«A±» у читателя меняют, сколько знаков влезает в строку. Поэтому постраничная разбивка считается
в браузере, из готовой вёрстки:

1. Текст оборачивается в `.book-stage` (фиксированная высота, `overflow: hidden`).
2. Внутри — `.book-flow` с `column-width: var(--page-width)`, `column-gap`, `height: 100%`,
   `column-fill: auto`.
3. Число страниц = `Math.round(flow.scrollWidth / (pageWidth + gap))`.
4. Переход на страницу N — `transform: translateX(-N * (pageWidth + gap))` на `.book-flow`
   (без пересборки DOM, только трансформация — это дёшево и не вызывает переверстку).

Разбивка при сборке (заранее нарезанные страницы) отвергается: она верна только для одного
размера экрана и одной гарнитуры, а при смене шрифта страницы «рвутся» посередине строки.

Важно: колонки создают **новый контекст**, поэтому `column-fill: auto` обязателен — иначе браузер
разливает текст равномерно по всем колонкам, и высота страниц скачет.

### 2.2. Два режима: одна страница и разворот

- `data-view="single"` — одна колонка шириной `min(72ch, 100%)`.
- `data-view="spread"` — две колонки, каждая шириной `calc((100% - gutter) / 2)`; листается
  сразу на две страницы, левая страница чётная, правая нечётная.
- Автовыбор: ширина ≥ 1024px → разворот, иначе одна страница. Выбор читателя хранится
  в `localStorage` (`book.view.v1`) и перекрывает автоопределение; на экране < 700px разворот
  принудительно выключается (две колонки по 300px нечитаемы).
- Единица листания — «лист»: в одиночном режиме 1 страница, в развороте 2.

### 2.2а. Включение по выбору читателя (не по умолчанию)

- В тулбаре страницы произведения у прозы появляется кнопка **«Режим книги»**; рядом с ней —
  обычные «A− / A+ / Режим чтения / Распечатать». Стихи кнопки не получают: там `pre-wrap`
  и книжная вёрстка им не нужна.
- По умолчанию кнопки «книга» нет в действии: страница — та же, что сейчас, никакой разметки
  `.book`, никакой колоночной вёрстки. Это важно и для SEO, и для тех, кому нужен просто текст.
- По клику подгружается `book.js` (`import()` — один файл, ~8 КБ) и включается книжный режим
  на текущем месте: прогресс сохраняется как доля прокрутки, читатель не «прыгает» в начало.
- Выбор запоминается в `localStorage` (`book.enabled.v1`) и в следующий раз применяется сам;
  «Обычный текст» в тулбаре книги возвращает страницу к текущему виду и тоже запоминает выбор.
- Если JS не загрузился, кнопка ничего не ломает: страница остаётся обычной.
- Конфиг: `reader.book = { available: true, default: false, sound: false, curl: "flat" }` —
  `available: false` убирает кнопку совсем (например, если у автора нет прозы).

Побочный, но полезный эффект: мы видим по Метрике (`book_open`), сколько читателей выбирают книгу
и на каких рассказах. Это решает вопрос «а нужен ли виджет» на данных, а не на вкусе.

### 2.3. Вёрстка текста (главное, ради чего всё делается)

- Гарнитура: тот же `--serif`, что у сайта (Literata/Georgia-стек), 18–20px, `line-height: 1.55`.
- Длина строки 60–75 знаков, выключка `text-align: justify`, переносы `hyphens: auto`,
  `hyphenate-limit-chars: 6 3 3` (не рвать короткие слова и имена), `lang="ru"` на контейнере.
- Абзацный отступ `text-indent: 1.5em`, без отбивки между абзацами (как в книге), кроме первого
  абзаца главы/страницы — `p:first-child { text-indent: 0 }` только на первой странице книги.
- Висячие строки: `orphans: 2; widows: 2` (поддержка в колоночной вёрстке частичная — проверять).
- Верх/низ страницы: поля 28–36px, колонтитул с номером страницы, зеркальные поля в развороте
  (внутреннее больше внешнего).
- Никаких `letter-spacing`, `first-letter` буквиц — в русской прозе это смотрится как сувенир.

### 2.4. Номера страниц

- Под каждой страницей — `стр. 12` (в развороте: слева «12», справа «13»), мелко, `aria-hidden="true"`.
- Отдельно, для скринридеров, — `aria-live="polite"`-регион: «Страница 12 из 47».
- Индикатор прогресса — тонкая полоса внизу (не влияет на вёрстку, `position: sticky`).

### 2.5. Перелистывание и звук

- Анимация: лист `.book-leaf` с `transform-origin: left center`, поворот `rotateY(-180deg)`
  за 420 мс, `perspective` на сцене; тень страницы (градиент) для объёма.
- Упрощённый режим (мобильные, слабые устройства, `prefers-reduced-motion: reduce`):
  сдвиг + короткое перекрёстное затухание 120 мс, без 3D.
- Звук: **синтез через WebAudio**, без файлов. Пара «щелчок + шелест» = короткий шумовой всплеск
  (буфер 60 мс белого шума) через полосовой фильтр 900–2500 Гц с быстрым спадом огибающей
  (`exponentialRampToValueAtTime`). Итог — ~30 строк кода, 1 КБ, никаких вопросов по лицензиям
  и никаких запросов к сети.
  - Громкость 0,18 по умолчанию, кнопка «звук вкл/выкл», состояние в `localStorage`.
  - `AudioContext` создаётся только по первому жесту (клик/клавиша) — иначе браузер блокирует звук.
  - При `prefers-reduced-motion` звук по умолчанию выключен.
  - Альтернатива, если захочется «настоящего» шелеста: запись CC0 с freesound.org, mp3 40–60 КБ,
    с указанием лицензии в подвале виджета. В план не входит, оставлена как развилка.

### 2.6. Доступность и SEO

- Текст остаётся в DOM целиком, виджет — прогрессивное улучшение: без JS страница выглядит
  как сейчас (обычная прокрутка). Класс `book-ready` ставится скриптом; без него книжные стили
  не применяются.
- Клавиатура: `←/→` лист, `Home/End` — начало/конец, `Space` — вперёд; фокус остаётся
  на контейнере (`tabindex="0"`, `role="region"`, `aria-roledescription="книга"`).
- Кнопка «Обычный текст» выключает виджет (и запоминает выбор) — это же спасение при любом сбое.
- Ссылки внутри текста и выделение мышью работают: колонки сдвигаются трансформацией,
  но остаются в потоке.
- Скринридер не должен читать «соседние» колонки как продолжение — контейнеру даётся
  `aria-label` с числом страниц, а смена страницы анонсируется регионом (п. 2.4).

### 2.7. Печать

`@media print`: `column-width: auto`, `height: auto`, снять трансформации, показать весь текст,
`p { break-inside: avoid }`. Кнопка «Распечатать» из тулбара продолжает работать — печатается
книга целиком, а не открытая страница.

## 2.8. Изгиб страницы и корешок: что сколько стоит

Короткий ответ: **корешок разворота — почти бесплатно, настоящий изгиб листа — дорого, и по
картинке он почти не отличается от «мягкого» варианта, пока текст остаётся текстом.**

Проблему нужно разделить на три вещи, которые часто путают:

1. **Корешок** — центральная тень разворота: две страницы сходятся, в середине темнее и уже.
   Это статика: `box-shadow: inset` по 30–40 px с каждой стороны + лёгкий градиент.
   **≈1 ч**, никаких рисков, даёт большую часть «ощущения книги».
2. **Перелистывание листа** — 3D-поворот жёсткой страницы `rotateY` с тенью на сгибе.
   **≈2 ч**, уже в плане.
3. **Настоящий изгиб** — страница гнётся дугой, текст «едет» по изогнутой поверхности.

Третье в браузере делается четырьмя способами, и все они с оговорками:

| Способ | Как | Срок | Минусы |
|---|---|---|---|
| Оверлей с `clip-path` + затенение | лист поворачивается, его край изогнут ломаной из 12–20 точек, по листу едет светотень; под ним настоящая страница меняется в конце | 6–8 ч | «гнётся» только бумага: сам текст листа не изгибается, либо его не видно во время анимации |
| Лист из полос | страница нарезается на 10–16 вертикальных полос, каждая — обёртка с тем же текстом со сдвигом и своим углом поворота | 10–14 ч | швы и дрожание текста на субпикселях, копирование и выделение на время анимации отключаются, дороже по вёрстке на слабых устройствах |
| SVG `foreignObject` → растр | страница снимается в картинку и гнётся уже картинка | 12–16 ч | текст превращается в изображение: пропадает выделение, ломается печать и скринридеры, нужен запасной путь |
| WebGL-меш | тот же растр кладётся на сетку и гнётся в шейдере, фотореалистичный загиб | 30–40 ч | самая тяжёлая ветка: растеризация страниц, шейдеры, тюнинг на мобильных, риск перегрева; без библиотек весь GL-код пишется руками |

Отдельная сложность: CSS **не умеет гнуть текст**. Любой настоящий изгиб — это либо нарезка
на полосы, либо превращение текста в картинку. Поэтому «как в iBooks» и «текст остаётся текстом»
— взаимоисключающие требования, и по плану мы выбираем текст.

**Решение:** в фазе 3 делаем корешок + плоский 3D-лист (≈3 ч суммарно). Если после живого
просмотра лист покажется жёстким — отдельной фазой добавляем «мягкий изгиб» оверлеем
(6–8 ч), это лучшее соотношение «эффект / цена / риски». Нарезку и WebGL в план не берём:
их цена в 4–10 раз выше, а выигрыш виден только в замедленной съёмке.

## 3. Архитектура файлов

```
src/book/
  book.css      — стили книги (сцена, колонки, колонтитул, лист, печать, reduced-motion)
  book.js       — пагинация, листание, режимы, звук (~250 строк)
scripts/build.mjs — включение виджета только у прозы: genre === 'Рассказ'
src/app.js    — точка входа: initBook() при наличии [data-book]
public/sound/ — пусто (звук синтезируется); каталог создаётся, если перейдём на файл
```

Разметка на странице произведения (у прозы):

```html
<section class="book" data-book data-title="…" tabindex="0" role="region" aria-roledescription="книга">
  <div class="book-toolbar">…кнопки: ‹ ›, режим, звук, шрифт A±, обычный текст, печать…</div>
  <div class="book-stage">
    <div class="book-flow" lang="ru">…абзацы…</div>
    <div class="book-footer"><span class="book-page-no"></span></div>
  </div>
  <div class="book-progress"><i></i></div>
  <p class="visually-hidden" aria-live="polite" data-book-live></p>
</section>
```

Ключевые функции `book.js`:

| Функция | Что делает |
|---|---|
| `measure()` | читает `scrollWidth`, считает `pages`, пишет `--pages`; только чтение — вызывается в `rAF` |
| `layout()` | пишет ширину колонки в CSS-переменные, применяет `translateX` (только запись) |
| `go(leaf, {instant})` | переход, звук, анонс, сохранение позиции |
| `setView('single'\|'spread')` | перестройка с сохранением прогресса (`page / pages`) |
| `resize()` | `ResizeObserver` + дебаунс 150 мс → `measure` → `layout` |
| `flipSound()` | WebAudio: шум + фильтр + огибающая, ленивое создание контекста |
| `exit()` | снять книжные классы, вернуть обычную страницу, запомнить выбор |

Позиция чтения сохраняется в `localStorage` (`book.page.<slug>.v1`) как доля, а не номер страницы:
после смены шрифта или ширины окна читатель возвращается примерно туда же.

## 4. Порядок работ

### Фаза 1. Каркас и колоночная пагинация (≈8 ч)

1. В `build.mjs` для прозы: текст разбить на `<p>` по пустой строке и выводить обёртку `.book`
   вместо блока `<div class="poem">` (у стихов ничего не меняется — там `pre-wrap` и отступы
   заданы пробелами). Строки внутри абзаца склеиваются через пробел. Разметка выводится всегда,
   но книжные стили и скрипт не применяются, пока читатель не выбрал режим.
2. Кнопка «Режим книги» в тулбаре у прозы + ленивая загрузка `book.js` по клику; «Обычный текст» —
   обратно; выбор в `localStorage`; без JS страница остаётся обычной.
3. `book.css`: сцена, колонки, `column-fill: auto`, поля, колонтитул.
4. `book.js`: `measure`/`layout`/`go`, кнопки ‹ ›, клавиатура, счётчик страниц.
5. Без анимации и звука — только «перелистывание» мгновенным сдвигом.

Приёмка: «Господин из Сан-Франциско» (65 тыс. знаков) листается до последней страницы, текст
не обрезан, при `Ctrl+±` и ресайзе ничего не рассыпается.

### Фаза 2. Режимы и номера страниц (≈4 ч)

1. Переключатель «Разворот / Одна страница», автоопределение, `localStorage`.
2. Номера страниц в колонтитуле (слева/справа в развороте), зеркальные поля.
3. Прогресс-полоса, `aria-live`-анонс.
4. Сохранение позиции чтения (доля) и возврат к ней.

Приёмка: переключение режимов на середине рассказа не сбрасывает позицию; в развороте левая
страница чётная; на 375px разворот недоступен.

### Фаза 3. Корешок, лист и звук (≈5 ч)

1. Корешок разворота: центральная тень и градиент по 30–40 px с каждой стороны (п. 2.8).
2. `rotateY`-лист, тень, 420 мс; упрощённый режим для `prefers-reduced-motion` и < 700px.
3. WebAudio-звук, кнопка mute, ленивый контекст, громкость 0,18.
4. Защита от «двойного» звука при быстром листании (очередь из одного перелистывания,
   анимация обрывается на середине).

Приёмка: звук включается только после жеста; при выключенном звуке — тишина; в Firefox
и Safari лист не «прыгает»; при `prefers-reduced-motion` анимации нет.

### Фаза 3а (по решению после просмотра). Мягкий изгиб листа (≈7 ч)

Оверлей с `clip-path` и светотенью вместо жёсткого листа (п. 2.8, способ 1). Делается только если
плоский поворот покажется «картонным»; на текст и доступность не влияет — анимируется бумага,
настоящая страница меняется в конце.

### Фаза 4. Тулбар, доступность, выход (≈4 ч)

1. Кнопки: ‹ ›, режим, звук, A−/A+, «Обычный текст», «Распечатать», «К началу».
2. Фокус, `aria`-атрибуты, анонсы, работа с клавиатуры по всей странице.
3. Кнопка выхода из книги и запоминание этого выбора.

Приёмка: прохождение страницы только с клавиатуры; скринридер (NVDA) читает «Страница N из M»;
выход из книги возвращает обычную прокрутку без перезагрузки.

### Фаза 5. Печать, отказы, гейты (≈3 ч)

1. `@media print` — весь текст, без колонок и трансформаций.
2. Без JS — обычная страница (проверить `javascript:false`).
3. Гейты в `verify.mjs`: наличие `book.js`/`book.css` в dist, размер `book.js` ≤ 12 КБ,
   наличие `data-book` у всех прозаических страниц и отсутствие у стихов, текст в HTML
   не короче исходного (сравнение длины после снятия тегов).
4. Событие Метрики `book_flip` (не чаще раза в 10 секунд).

### Фаза 6. QA и полировка (≈5 ч)

Матрица: Chrome, Firefox, Safari (десктоп), iOS Safari, Android Chrome; ширины 320 / 768 / 1024 /
1440; A± три шага; самый короткий (3,6 тыс.) и самый длинный (65 тыс.) рассказ; тёмная и светлая
темы; печать из Chrome и Safari.

Итого ≈29 ч; MVP (фазы 1–2) ≈12 ч, полноценная «книга» со звуком и анимацией — фазы 1–4 ≈21 ч,
с мягким изгибом — ≈28 ч.

## 5. Приёмочные критерии (проверяются на живой сборке)

0. По умолчанию страница произведения выглядит и весит как сейчас: книжные стили не применены,
   `book.js` не загружен (проверяется в DevTools → Network), кнопка «Режим книги» на месте.
1. Текст рассказа доступен полностью: сумма текста всех страниц равна тексту в `works.json`.
2. Последняя страница достижима, обрезки нет ни на одной ширине из матрицы.
3. Листание работает мышью, тапом и с клавиатуры; звук синхронен с анимацией.
4. Разворот и одиночный режим переключаются без потери позиции.
5. Без JS и пока режим не выбран текст читается как раньше; «Обычный текст» возвращает страницу
   к текущему виду без перезагрузки и запоминает выбор на устройстве.
5а. В развороте виден корешок; при мягком изгибе (фаза 3а) анимация не мешает выделению текста
   после перелистывания.
6. Печать даёт весь рассказ.
7. `npm run verify` — 0 ошибок, 0 предупреждений; размер `book.js` + `book.css` ≤ 20 КБ суммарно.
8. Метрика видит `book_flip`; ни одного сетевого запроса за звуком.

## 6. Риски и что с ними делать

| Риск | Как снимаем |
|---|---|
| Safari считает `scrollWidth` колонок с округлением вниз → «лишняя» пустая страница | считать `Math.round`, а не `ceil`; тест на Safari первым делом |
| Разная метрика шрифтов (Windows/macOS) рвёт страницу иначе | не хранить номер страницы как позицию чтения — только долю |
| `column-fill: auto` в Firefox иначе распределяет контент | проверять обе ветки; при расхождении — фиксировать высоту сцены в px |
| Автовоспроизведение звука блокируется | контекст только по жесту; при отказе — тихо живём без звука |
| Текст «уезжает» из DOM при перелистывании | никакой виртуализации: весь текст всегда в DOM, сдвиг только трансформацией |
| Виджет ломает SEO | текст не скрывается, кнопка «Обычный текст», SSR-разметка та же |
| Скринридер читает колонки подряд | `aria-live`-анонс + `aria-roledescription`, тест NVDA в фазе 4 |
| Читатель хочет просто прочитать | режим книги выключен по умолчанию; кнопка «Обычный текст» на первом плане тулбара, выбор запоминается |
| «Книга» навязана тем, кому она не нужна | по умолчанию её нет; включение только по клику, с сохранением выбора |
| Изгиб требует превратить текст в картинку | изгиб анимируется на оверлее-«бумаге», текст остаётся текстом (п. 2.8) |

## 7. Что сознательно не делаем

- Не подключаем turn.js / StPageFlip и подобное: вес, jQuery, недоступность, чужой код в проекте.
- Не рисуем текст в `<canvas>`: это убивает поиск, копирование и скринридеры.
- Не режем страницы на сборке: невозможно при плавающей ширине окна.
- Не делаем «настоящий» загиб страницы с искажением текста (WebGL/фильтры): дорого по
  производительности и ломает выделение; 3D-поворот листа даёт нужное ощущение за 20 строк CSS.
- Не добавляем шрифты: системный serif-стек уже совпадает с остальным сайтом.
