# Книжный виджет в библиотеке: план реализации

Задача: при открытии рассказа показывать текст не как веб-страницу, а как печатную книгу —
с постраничной разбивкой, номерами страниц, нормальной вёрсткой (выключка, переносы, абзацный
отступ), переключателем «разворот / одна страница», **листом с мягким изгибом и звуком
перелистывания**. Объём — полная книга: анимация и звук входят в основной план, а не в «когда-нибудь».

Документ фиксирует решения, порядок работ, приёмочные критерии и риски. Реализация — отдельными
коммитами по фазам, каждая фаза заканчивается зелёным `npm run verify`.

**Виджет не включён по умолчанию.** По умолчанию страница произведения остаётся такой, как
сейчас: обычный текст с прокруткой. Режим книги — выбор читателя: кнопка «Режим книги» в тулбаре,
выбор запоминается на устройстве, есть возврат «Обычный текст». Скрипт книги при этом не грузится
до первого включения — вес страницы, скорость и SEO остаются прежними.

Дата: 01.11.2026. Проект: `bunin-site` (36 рассказов, 3,6–65 тысяч знаков). После приёмки —
перенос в `esenin-dashboard` (правило серии).

## 1. Что уже есть и на что опираемся

- Тексты лежат в `data/works.json` как чистый текст с абзацами через пустую строку; HTML внутри нет.
- На странице произведение выводится одним блоком: `<div class="poem">` + `white-space: pre-wrap`
  (стихи держатся только на этой разметке). Для книги этого мало: нужны настоящие `<p>`, иначе
  абзацный отступ и переносы не работают, — значит, для прозы при сборке текст разбивается
  на абзацы по пустой строке.
- Страница произведения собирается в `scripts/build.mjs` (`workPage()`): заголовок, тулбар
  (`data-poem-action`: шрифт, режим чтения, без оформления, печать, копирование), текст, источник.
- Вся интерактивность — ванильный `src/app.js` (16 КБ, без библиотек), стили — `src/styles.css`.
- Есть страница «для печати» (`/print/`) и печатные стили.
- Сайт статический, деплой на GitHub Pages, `npm run verify` — жёсткий гейт.

Отсюда два ограничения, которые определяют всю архитектуру: **никаких внешних библиотек**
(перелистывалки типа turn.js весят 30–60 КБ, ломают доступность и требуют jQuery) и **текст обязан
остаться в HTML** — иначе страницы выпадают из поиска.

## 1а. Что уже проверено прототипом

Собран одноразовый вариант (не в репозитории): «Господин из Сан-Франциско» разбит на 53 абзаца
по `<p>`, обёрнут в колонки `column-width: 480px`, сцена 1100×700, `column-fill: auto`,

| слов | 6 580 |

Выводы, которые план уже учитывает:

- техника работает и даёт правдоподобную книжную ёмкость (~940 знаков на страницу — это примерно

  дробной ширины колонки, и `ceil` дал бы 47-ю пустую страницу;
- оценка объёма книги для остальных рассказов: `страниц ≈ знаков / 940` (медианный рассказ

- проверен только Chromium: Safari и Firefox остаются в матрице QA (фаза 6), потому что именно они
  расходятся в подсчёте `scrollWidth` и в распределении `column-fill`.

**Решение:** вендорим `page-flip.browser.js` (пин 2.0.7, файл кладём в репозиторий с сохранённым
заголовком MIT — никакой зависимости от npm в рантайме и никакого supply-chain), а всё остальное
пишем своё. Экономия против собственного изгиба — ≈11 часов, и мы не отлаживаем геометрию листа.

## 2. Ключевые решения

### 2.1. Разбивка на страницы — во время чтения, а не при сборке

Печатная книга имеет фиксированный формат, браузер — нет: ширина окна, размер шрифта и настройка
«A±» у читателя меняют, сколько знаков влезает в строку. Поэтому постраничная разбивка считается
в браузере, из готовой вёрстки:

1. Текст оборачивается в `.book-stage` (фиксированная высота, `overflow: hidden`).
2. Внутри — `.book-flow` с `column-width: var(--page-width)`, `column-gap`, `height: 100%`,
   `column-fill: auto`.
3. Число страниц = `Math.round(flow.scrollWidth / (pageWidth + gap))`.
4. Переход на страницу N — `transform: translateX(-N * (pageWidth + gap))` на `.book-flow`
   (без пересборки DOM, только трансформация — это дёшево и не вызывает переверстку).

Разбивка при сборке (заранее нарезанные страницы) отвергается: она верна только для одного
размера экрана и одной гарнитуры, а при смене шрифта страницы «рвутся» посередине строки.

Библиотеке StPageFlip нужны готовые элементы-страницы, поэтому после измерения колонок текст
нарезается по границам `Range`-диапазонов: каждая буква попадает ровно в одну страницу, дублей нет,
выделение и поиск по странице работают. Это единственное место, где нужна аккуратность: границы
колонок округляются вниз, иначе последняя строка переползает на следующую страницу.

Важно: колонки создают **новый контекст**, поэтому `column-fill: auto` обязателен — иначе браузер
разливает текст равномерно по всем колонкам, и высота страниц скачет.

### 2.2. Два режима: одна страница и разворот

- `data-view="single"` — одна колонка шириной `min(72ch, 100%)`.
- `data-view="spread"` — две колонки, каждая шириной `calc((100% - gutter) / 2)`; листается
  сразу на две страницы, левая страница чётная, правая нечётная.
- Автовыбор: ширина ≥ 1024px → разворот, иначе одна страница. Выбор читателя хранится
  в `localStorage` (`book.view.v1`) и перекрывает автоопределение; на экране < 700px разворот
  принудительно выключается (две колонки по 300px нечитаемы).
- Единица листания — «лист»: в одиночном режиме 1 страница, в развороте 2.

### 2.2а. Включение по выбору читателя (не по умолчанию)

- В тулбаре страницы произведения у прозы появляется кнопка **«Режим книги»**; рядом с ней —
  обычные «A− / A+ / Режим чтения / Распечатать». Стихи кнопки не получают: там `pre-wrap`
  и книжная вёрстка им не нужна.
- По умолчанию кнопки «книга» нет в действии: страница — та же, что сейчас, никакой разметки
  `.book`, никакой колоночной вёрстки. Это важно и для SEO, и для тех, кому нужен просто текст.
- По клику подгружается `book.js` (`import()` — один файл, ~8 КБ) и включается книжный режим
  на текущем месте: прогресс сохраняется как доля прокрутки, читатель не «прыгает» в начало.
- Выбор запоминается в `localStorage` (`book.enabled.v1`) и в следующий раз применяется сам;
  «Обычный текст» в тулбаре книги возвращает страницу к текущему виду и тоже запоминает выбор.
- Если JS не загрузился, кнопка ничего не ломает: страница остаётся обычной.
- Конфиг: `reader.book = { available: true, default: false, sound: false, curl: "flat" }` —
  `available: false` убирает кнопку совсем (например, если у автора нет прозы).

Побочный, но полезный эффект: мы видим по Метрике (`book_open`), сколько читателей выбирают книгу
и на каких рассказах. Это решает вопрос «а нужен ли виджет» на данных, а не на вкусе.

### 2.3. Вёрстка текста (главное, ради чего всё делается)

- Гарнитура: тот же `--serif`, что у сайта (Literata/Georgia-стек), 18–20px, `line-height: 1.55`.
- Длина строки 60–75 знаков, выключка `text-align: justify`, переносы `hyphens: auto`,
  `hyphenate-limit-chars: 6 3 3` (не рвать короткие слова и имена), `lang="ru"` на контейнере.
- Абзацный отступ `text-indent: 1.5em`, без отбивки между абзацами (как в книге), кроме первого
  абзаца главы/страницы — `p:first-child { text-indent: 0 }` только на первой странице книги.
- Висячие строки: `orphans: 2; widows: 2` (поддержка в колоночной вёрстке частичная — проверять).
- Верх/низ страницы: поля 28–36px, колонтитул с номером страницы, зеркальные поля в развороте
  (внутреннее больше внешнего).
- Никаких `letter-spacing`, `first-letter` буквиц — в русской прозе это смотрится как сувенир.

### 2.4. Номера страниц

- Под каждой страницей — `стр. 12` (в развороте: слева «12», справа «13»), мелко, `aria-hidden="true"`.
- Отдельно, для скринридеров, — `aria-live="polite"`-регион: «Страница 12 из 47».
- Индикатор прогресса — тонкая полоса внизу (не влияет на вёрстку, `position: sticky`).

### 2.5. Перелистывание и звук

- Анимация: отдана StPageFlip (п. 2.8) — soft-страницы с изгибом, тень, перетаскивание мышью
  и пальцем; `flippingTime: 700`, обложка жёсткая (`data-density="hard"` на первой и последней).
- Упрощённый режим: при `prefers-reduced-motion: reduce` — `flippingTime: 0` и без теней,
  страница меняется мгновенно; звук и смена страницы остаются.
- Звук: **синтез через WebAudio**, без файлов. Пара «щелчок + шелест» = короткий шумовой всплеск
  (буфер 60 мс белого шума) через полосовой фильтр 900–2500 Гц с быстрым спадом огибающей
  (`exponentialRampToValueAtTime`). Итог — ~30 строк кода, 1 КБ, никаких вопросов по лицензиям
  и никаких запросов к сети.
  - Громкость 0,18 по умолчанию, кнопка «звук вкл/выкл», состояние в `localStorage`.
  - `AudioContext` создаётся только по первому жесту (клик/клавиша) — иначе браузер блокирует звук.
  - При `prefers-reduced-motion` звук по умолчанию выключен.
  - Альтернатива, если захочется «настоящего» шелеста: запись CC0 с freesound.org, mp3 40–60 КБ,
    с указанием лицензии в подвале виджета. В план не входит, оставлена как развилка.

### 2.6. Доступность и SEO

- Текст остаётся в DOM целиком, виджет — прогрессивное улучшение: без JS страница выглядит
  как сейчас (обычная прокрутка). Класс `book-ready` ставится скриптом; без него книжные стили
  не применяются.
- Клавиатура: `←/→` лист, `Home/End` — начало/конец, `Space` — вперёд; фокус остаётся
  на контейнере (`tabindex="0"`, `role="region"`, `aria-roledescription="книга"`).
- Кнопка «Обычный текст» выключает виджет (и запоминает выбор) — это же спасение при любом сбое.
- Ссылки внутри текста и выделение мышью работают: колонки сдвигаются трансформацией,
  но остаются в потоке.
- Скринридер не должен читать «соседние» колонки как продолжение — контейнеру даётся
  `aria-label` с числом страниц, а смена страницы анонсируется регионом (п. 2.4).

### 2.7. Печать

`@media print`: `column-width: auto`, `height: auto`, снять трансформации, показать весь текст,
`p { break-inside: avoid }`. Кнопка «Распечатать» из тулбара продолжает работать — печатается
книга целиком, а не открытая страница.

## 2.8. Изгиб страницы и корешок: что берёт библиотека, что наше

Настоящий изгиб — единственная часть, которую не стоило писать руками, и StPageFlip его отдаёт:

- тип страницы задаётся атрибутом `data-density="soft" | "hard"`; `soft` — гнущийся лист
  с тенью, `hard` — жёсткая обложка. Обложкой делаем первую и последнюю страницу.
- тени рисует сама библиотека (`drawShadow`, `maxShadowOpacity`), тень «уезжает» вместе с листом.
- перетаскивание мышью и пальцем — из коробки (`useMouseEvents`), угол листа — `corner: 'top' | 'bottom'`.
- корешок разворота (статичная центральная тень, чтобы страницы сходились) добавляем своим CSS:
  две `inset`-тени по 30–40 px — 1 час работы, и разворот сразу читается как книга.
- длительность задаётся `flippingTime` (ставим 700 мс; для `prefers-reduced-motion` — 0
  и без 3D, библиотека в этом случае просто меняет страницу).

Что остаётся на нас: пагинация, нарезка текста на страницы, номера, звук, кнопки, доступность,
печать и откаты. Плата за библиотеку — 44 КБ (10,2 КБ gzip) и риск того, что она не обновляется
с 2021 года; поэтому файл вендорим, версию пиним и оставляем полный откат в обычный текст.


## 3. Архитектура файлов

```
src/book/
  stpageflip.js — вендоренный page-flip.browser.js 2.0.7 (MIT, 44 КБ / 10,2 КБ gzip), заголовок лицензии сохранён
  book.css      — сцена, страницы, колонтитул, корешок, печать, reduced-motion
  book.js       — пагинация, нарезка текста по страницам, кнопки, клавиатура, звук (~350 строк, ≤ 12 КБ)
scripts/build.mjs — у прозы: абзацы в `<p>`, обёртка `.book`-источник, кнопка «Режим книги»
scripts/verify.mjs — гейты: файлы на месте, лицензия в шапке, бюджеты, целостность текста
src/app.js    — ленивый `import('./book/book.js')` по клику
```

Разметка на странице произведения — по умолчанию та же, что сейчас: текст обычным потоком.
Книжную структуру строит скрипт после выбора режима.

```html
<div class="poem" data-book-source>…абзацы <p>…</p>…</div>
<button class="book-open" data-book-open>Режим книги</button>
<!-- после клика скрипт создаёт: -->
<section class="book" data-book tabindex="0" role="region" aria-roledescription="книга">
  <div class="book-toolbar">…‹ ›, режим, звук, A±, обычный текст, печать…</div>
  <div class="book-stage"><div class="book-pages">…по одному элементу на страницу…</div></div>
  <div class="book-progress"><i></i></div>
  <p class="visually-hidden" aria-live="polite" data-book-live></p>
</section>
```

Ключевые функции `book.js`:

| Функция | Что делает |
|---|---|
| `paginate()` | колонки на скрытой копии текста → измеряет границы колонок |
| `slicePages()` | через `Range` режет текст по границам колонок: каждая буква попадает ровно в одну страницу |
| `buildPages()` | собирает элементы `.page` (первая и последняя — `data-density="hard"`) |
| `mount()` | `new St.PageFlip(...)`, `loadFromHtml`, подписка на `flip`, `changeOrientation` |
| `remount()` | `destroy()` + `paginate()` + `buildPages()` + `loadFromHtml` при ресайзе (дебаунс 200 мс) |
| `flipSound(dir)` | WebAudio: шум + полосовой фильтр + огибающая, ленивое создание контекста |
| `exit()` | `destroy()`, вернуть обычный текст, запомнить выбор |

Позиция чтения хранится долей (`page / pages`) в `localStorage` (`book.page.<slug>.v1`), а не номером
страницы: после смены шрифта или ширины окна читатель возвращается туда же.

## 4. Порядок работ

Порядок продиктован рисками: сначала пагинация и нарезка (самое хрупкое), потом интеграция
библиотеки (самое чужое), звук и доступность — после того, как листание уже работает.

### Фаза 1. Пагинация и нарезка текста (≈10 ч)

1. `build.mjs`: у прозы абзацы в `<p>` (склейка строк внутри абзаца), обёртка `data-book-source`,
   кнопка «Режим книги». У стихов — без изменений.
2. `book.js`: скрытая колоночная копия текста → замер границ колонок при заданной сцене.
3. `slicePages()`: нарезка по `Range` (каждая буква — в одной странице), сборка элементов `.page`.
4. Контроль полноты: сумма текста страниц обязана совпадать с исходным текстом.

Приёмка: «Господин из Сан-Франциско» даёт 46 страниц, текст не потерян и не задублирован;
при `Ctrl+±` и ресайзе страницы пересобираются без потери места чтения.

### Фаза 2. Включение по выбору, разворот и номера (≈6 ч)

1. Ленивая загрузка `book.js` по клику; «Обычный текст» — обратно; выбор в `localStorage`.
2. «Разворот / Одна страница» — через ширину сцены (у StPageFlip это landscape/portrait),
   автоопределение по ширине окна, выбор запоминается.
3. Номера страниц в колонтитуле, корешок разворота.
4. Прогресс-полоса и `aria-live`-анонс «Страница N из M».

Приёмка: до включения режима `book.js` в Network нет; переключение режимов не сбрасывает место;
на 375px разворот недоступен.

### Фаза 3. Интеграция библиотеки (≈4 ч)

1. `mount()`: `new St.PageFlip`, `loadFromHtml`, `flippingTime: 700`, `drawShadow`,
   `maxShadowOpacity`, `useMouseEvents`, обложка `hard`.
2. Подписка на `flip` (номера, прогресс, звук) и `changeOrientation`.
3. `remount()` при ресайзе и смене шрифта: `destroy()` → новая пагинация → `loadFromHtml`.
4. Откат: если библиотека не загрузилась, остаёмся на обычном тексте.

Приёмка: перелистывание мышью, пальцем и кнопками; после ресайза книга открыта на том же месте;
без библиотеки страница работает как раньше.

### Фаза 4. Звук (≈3 ч)

1. WebAudio-синтез, два варианта: «вперёд» — шумовой всплеск 60 мс через полосовой фильтр
   900–2600 Гц; «назад» — ниже по частоте и тише.
2. Синхронизация с началом анимации (событие `flip`), громкость 0,18, кнопка mute с запоминанием.
3. `AudioContext` — только по жесту; при `prefers-reduced-motion` звук по умолчанию выключен;
   не больше одного звука на 120 мс.

Приёмка: при mute — тишина; нет двойного звука при удержании стрелки.

### Фаза 5. Тулбар и доступность (≈4 ч)

1. Кнопки: ‹ ›, режим, звук, A−/A+, «Обычный текст», «К началу», «Распечатать».
2. Клавиатура (←/→, Home/End, Space), фокус, `role="region"`, анонсы страниц.
3. Выход из книги и запоминание выбора.

Приёмка: страница проходится с клавиатуры без мыши; NVDA читает «Страница N из M».

### Фаза 6. Печать, отказы, гейты (≈3 ч)

1. `@media print`: обычный поток текста, без сцены и трансформаций; печатается весь рассказ.
2. Откаты: нет JS, нет библиотеки, ошибка в скрипте — читается обычный текст.
3. Гейты `verify.mjs`: наличие `stpageflip.js`, `book.js`, `book.css`; заголовок MIT в вендоренном
   файле; бюджеты (stpageflip ≤ 50 КБ, book.js + book.css ≤ 20 КБ); целостность текста;
   `data-book-source` только у прозы.
4. Метрики: `book_open`, `book_flip` (не чаще раза в 10 с), `book_sound`.

### Фаза 7. QA и полировка (≈5 ч)

Матрица: Chrome, Firefox, Safari (десктоп), iOS Safari, Android Chrome; ширины 320 / 768 / 1024 /
1440; A± три шага; самый короткий (3,6 тыс.) и самый длинный (65 тыс.) рассказ; обе темы; печать
из Chrome и Safari. Отдельно Safari: подсчёт границ колонок и поведение `Range` там расходятся.

Итого ≈35 ч: MVP (фазы 1–2) ≈16 ч, «книга с анимацией и звуком» (фазы 1–5) ≈27 ч,
полная версия с гейтами и QA — ≈35 ч.

## 5. Приёмочные критерии (проверяются на живой сборке)

0. По умолчанию страница произведения выглядит и весит как сейчас: книжные стили не применены,
   `book.js` не загружен (DevTools → Network), кнопка «Режим книги» на месте.
1. **Целостность текста:** сумма текста всех страниц совпадает с текстом в `works.json`
   символ в символ (с точностью до склейки переносов строк). Ни потерь, ни дублей.
2. Последняя страница достижима, обрезки нет ни на одной ширине из матрицы.
3. Листание работает мышью, пальцем и с клавиатуры; звук стартует вместе с анимацией,
   «назад» звучит ниже и тише; при mute — тишина.
4. Разворот и одиночный режим переключаются без потери места чтения; в развороте виден корешок.
5. Без JS и пока режим не выбран текст читается как раньше; «Обычный текст» возвращает страницу
   к текущему виду без перезагрузки и запоминает выбор.
6. Печать даёт весь рассказ (не одну открытую страницу).
7. `npm run verify` — 0 ошибок, 0 предупреждений; `stpageflip.js` ≤ 50 КБ, `book.js` + `book.css`
   ≤ 20 КБ; в шапке вендоренного файла сохранён MIT.
8. Метрика видит `book_flip`; ни одного сетевого запроса за звуком; `<canvas>` в книжном режиме
   не появляется (текст остаётся текстом).

## 6. Риски и что с ними делать

| Риск | Как снимаем |
|---|---|
| StPageFlip не обновляется с 2021 года, 48 открытых issue | файл вендорим (44 КБ) и пиним версию 2.0.7; все наши функции — вне библиотеки; полный откат в обычный текст по кнопке и при любой ошибке |
| Safari: `Range` и границы колонок считаются иначе → текст «съезжает» | тест Safari первым; округление границ колонок вниз; при расхождении — пересчёт по фактическому `getBoundingClientRect` текстовых строк |
| Библиотека клонирует страницы в portrait-режиме | проверять число текстовых узлов после смены ориентации; при дублях — `destroy()` + `loadFromHtml` вместо переключения на лету |
| Разная метрика шрифтов (Windows/macOS) рвёт страницу иначе | не хранить номер страницы как позицию чтения — только долю |
| Автовоспроизведение звука блокируется | контекст только по жесту; при отказе — тихо живём без звука |
| Текст «уезжает» из DOM при перелистывании | никакой виртуализации: текст нарезан по страницам один раз, каждая буква — в одной странице |
| Виджет ломает SEO | текст не скрывается, кнопка «Обычный текст», серверная разметка та же |
| Скринридер читает страницы подряд | `aria-live`-анонс + `aria-roledescription`, тест NVDA в фазе 5 |
| Читатель хочет просто прочитать | режим выключен по умолчанию, включение только по клику, выбор запоминается |
| Нарезка теряет или дублирует символы | сверка суммы текста страниц с исходником в `verify` и в консоли при разработке |

## 7. Что сознательно не делаем

- Не пишем свой изгиб листа: эту часть отдаём StPageFlip (п. 1б, 2.8). Своя реализация стоила
  ≈11 часов и требовала отладки геометрии на четырёх браузерах.
- Не берём библиотеки, которые превращают текст в картинку (`flipbook-viewer`, WebGL-меши,
  `foreignObject`-растр): минус выделение, печать и скринридеры.
- Не подключаем turn.js (jQuery + платная лицензия) и epub.js (300+ КБ, пагинация без анимации).
- Не режем страницы на сборке: невозможно при плавающей ширине окна.
- Не добавляем npm-зависимость в рантайм: вендоренный файл, ноль запросов к сети.
- Не добавляем шрифты: системный serif-стек уже совпадает с остальным сайтом.

## 8. Перенос в серию

После приёмки в `bunin-site`: скопировать `src/book/` (включая вендоренный `stpageflip.js` и его
лицензию), вставку разметки в `workPage()`, гейты `verify.mjs` и пункт конфига в `esenin-dashboard`;
проверить на «Яре» и «Стране негодяев» (крупные вещи) и на коротком рассказе. Проза в есенинском
проекте есть — виджет включается тем же признаком жанра. Затем добавить `src/book/` и гейты
в скаффолд `new_author_site.py`, чтобы новый автор получал книгу сразу.
