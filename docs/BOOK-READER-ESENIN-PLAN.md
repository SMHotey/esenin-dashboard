## 2. Разбивка текста на абзацы (ядро фазы 1)

Правила применяются к тексту нестихотворных произведений при сборке; стихи и поэмы идут прежним
путём (`pre-wrap`, ничего не меняется).

1. Нормализация: убрать `\r`, обрезать строки по краям, схлопнуть 3+ пустых строки в одну,
   сохранить исходную длину текста до и после (для гейта целостности).
2. Разбить на блоки по пустой строке.
3. Внутри блока — построчный разбор:
   - строка из одних цифр (1–4 знака) → структурная строка, **не выбрасывается**:
     1–3 знака → номер части `<p class="book-part">1</p>`, 4 знака в диапазоне 1900–1999 →
     дата `<p class="book-date">1916</p>` (так в «У белой воды» части 1, 2, 3, а в автобиографиях
     даты написания);
   - строка из римских цифр (`I`…`XX`, с точкой или без) → заголовок части `<p class="book-part">I</p>`;
   - строка капслоком, ≤ 40 знаков, без завершающей точки → подзаголовок `<h3 class="book-head">`
     (это ровно «ЭЛИС-АЛЕНД», «НЬЮ-ЙОРК», «БРОДВЕЙ»);
   - подряд ≥ 2 строки, каждая ≤ 55 знаков, → **стихотворная цитата**: блок `<div class="book-verse">`
     со строками через `<br>`, без абзацного отступа (проверено: 11 таких блоков в «Ярославны
     плачут», 3 в «Ключи Марии», 2 в «Отчем слове», 1 в «О сборниках…»);
   - иначе строка приклеивается к текущему абзацу через пробел; если строк несколько и все
     длинные (≥ 56 знаков) — каждая строка становится отдельным `<p>` (так собираются автобиографии).
4. Результат — массив абзацев с типами `p` / `verse` / `part` / `date` / `head`; на странице это
   `<div class="poem" data-book-source>…</div>`.
5. Исключения — в `data/book-overrides.json` (по slug: принудительно `verse`, `paragraphs`, `part`,
   `head`). Файл нужен потому, что капслок-подзаголовок и крик в тексте неотличимы формально;
   заводим его пустым и заполняем только при конкретной ошибке, а не заранее.
6. Контроль: `сумма текста всех абзацев == нормализованный исходник` — с точностью до схлопнутых
   пробелов, без вычетов: ничего не выбрасывается. Проверяется и в сборке (падает сборка), и в `verify`.

Пока правила не подтверждены на всех 17 текстах, кнопку не включаем: половина фазы 1 — это
именно проверка на «Ключи Марии» и «Железном Миргороде», а не написание кода.

## 4. Интеграция библиотеки: конкретика под этот проект

Общий план выбрал StPageFlip; здесь важны три детали, которых в нём нет.

1. **Файл — UMD, не ES-модуль.** `page-flip.browser.js` выставляет глобал `window.St.PageFlip`.
   Поэтому `book.js` не импортирует его, а один раз вставляет `<script src="/book/stpageflip.js?v=…">`
   и ждёт `onload`; повторный вызов переиспользует промис. Это же даёт корректный откат: если
   скрипт не загрузился — остаёмся на обычном тексте, без исключения в консоли.
2. **CSP.** `build.mjs:1961–1964` собирает заголовок с `style-src 'self' 'unsafe-inline'` и
   `script-src 'self' 'unsafe-inline'` — библиотеке этого достаточно (она пишет инлайновые стили и
   трансформации). Но заголовок уезжает в `_headers`, который читают только Netlify и Cloudflare
   Pages; GitHub Pages его игнорирует. Значит на боевом домене ограничений нет, а на резервных
   площадках конфиг уже совместим — проверять нечего, но и ломать нельзя: никаких новых источников
   скриптов не появляется.
3. **Кэш.** В `_headers` три записи `immutable` — `/styles.css`, `/app.js`, `/theme.js`. Нужна
   четвёртая: `/book/*`. Хеш `assetVersion` расширяем на файлы книги, иначе после правки `book.js`
   браузер отдаст старую версию из кэша (у книги свой URL, но `?v=` у него будет прежний).

Стили книги подключаются не ссылкой в `<head>`, а из `book.js` (`<link>` с `onload`) — иначе 5 КБ
CSS едут на каждой странице сайта ради функции, которую включает меньшинство.

## 5. Пагинация, нарезка, режимы, позиция чтения

Здесь ничего нового против общего плана (п. 2.1–2.4), фиксирую параметры под этот проект:

- Сцена книги: ширина `min(1100px, 100%)`, высота `70vh` (не меньше 480px), `column-width: 480px`,
  `column-gap: 60px`, `column-fill: auto`, `hyphens: auto`, `lang="ru"`, `text-align: justify`.
- Число страниц: `Math.round(flow.scrollWidth / (pageWidth + gap))` — проверено прототипом на
  «Господине из Сан-Франциско» (46 страниц, ёмкость ≈ 940 знаков). Здесь ожидаемые величины:
  «Бобыль и Дружок» ≈ 5 страниц, «У белой воды» ≈ 16, «Железный Миргород» ≈ 17, «Ключи Марии» ≈ 41.
- Нарезка по `Range`: границы колонок округляются **вниз**; каждая буква попадает ровно в одну
  страницу; проверка — сумма текста страниц равна тексту `.poem[data-book-source]`.
- Разворот / одна страница — через ширину сцены (у библиотеки это `landscape`/`portrait`).
  Автоопределение: ≥ 1024 px — разворот, < 700 px — принудительно одна. Выбор в `localStorage`
  (`book.view.v1`), позиция — долей (`book.page.<slug>.v1`), не номером страницы.
- `remount()` при ресайзе и смене кегля: `destroy()` → пагинация → `loadFromHtml`, дебаунс 200 мс.
  Кегль в книге — свой (`--book-size`, 18/20/22 px), чтобы не зависеть от `poem-size` обычной вёрстки.
- Корешок: две `inset`-тени по 34 px на стыке в развороте, только в `landscape`.

## 6. Включение по выбору и откат

- Кнопка `data-poem-action="book"` — рядом с «Режим чтения», только у 17 текстов из п. 1.
- До клика: `book.js` не загружен (проверяется в DevTools → Network), книжного CSS нет, разметка
  `.poem` та же, что сейчас. Это приёмочный пункт № 0 общего плана.
- После клика: подмена `.poem` на `<section class="book">`, тулбар книги, `localStorage.book.enabled.v1`.
- «Обычный текст» и Esc в книге — полный `destroy()`, возврат к `.poem` на том же месте
  (позиция пересчитывается из доли обратно в `scrollTop`).
- Любая ошибка в `book.js` (в том числе отказ WebAudio) не должна оставлять пустой экран:
  обёртка `try/catch` вокруг `mount()`, при исключении — `exit()` и обычный текст.

## 7. Звук, доступность, печать — коротко, как в общем плане

- Звук: WebAudio-синтез, шумовой всплеск 60 мс через полосовой фильтр 900–2600 Гц; «назад» — ниже
  и тише; громкость 0,18; `AudioContext` только по жесту; не чаще одного звука в 120 мс; mute
  в `localStorage` (`book.sound.v1`); при `prefers-reduced-motion` выключен по умолчанию.
- Клавиатура: ←/→, Home/End, Space; `role="region"`, `aria-roledescription="книга"`,
  `aria-live`-анонс «Страница N из M»; номера страниц `aria-hidden`.
- Печать: `@media print` — снять трансформации и сцену, `column-width: auto`, `height: auto`,
  печатается весь текст. Существующие правила (`styles.css:884–890`) не конфликтуют: `.poem-tools`
  уже скрыт, `.poem` печатается 14pt.

## 8. Гейты в `scripts/verify.mjs`

Новый блок после «--- тексты произведений ---» (`verify.mjs:361`), стиль тот же, что у остальных:
ошибка — `errors.push`, отсутствие — предупреждение только где оно законно.

1. `dist/book/book.js`, `dist/book/book.css`, `dist/book/stpageflip.js` существуют.
2. В `stpageflip.js` сохранён заголовок MIT (`@license`/`MIT` и `StPageFlip` в первых 2 КБ).
3. Бюджеты по размеру файлов на диске: `stpageflip.js` ≤ 50 КБ, `book.js` + `book.css` ≤ 20 КБ.
4. `data-book-source` стоит **ровно у 17** страниц произведений и **ни у одного** стихотворения/поэмы
   (сверка по `data/works.json`).
5. Ни в одном собранном HTML нет `<canvas>` (текст не растеризуется).
6. Текст не потерян: для каждого текста с книгой `chars` из `works.json` равен длине текста,
   собранного из абзацев страницы (без вычетов).
7. `book.js` не упоминается в HTML как `<script src>` — только динамический импорт (проверка того,
   что ленивость не сломали).
8. Кнопка книги есть у всех 17 и отсутствует у 8 коротких.

## 12. Риски, специфичные для этого репозитория

| Риск | Как снимаем |
|---|---|
| Нормализация испортит текст: склеит абзацы автобиографий или потеряет части «Миргорода» | правила п. 2 + оверрайды + гейт суммы текста; проверка глазами на 6 контрольных текстах до включения кнопки |
| Стихотворные цитаты внутри статей («Ключи Марии», «Ярославны плачут») склеятся в прозу | эвристика коротких строк + блок `book-verse`; при промахе — запись в `book-overrides.json` |
| Вендоренный UMD-файл не обновится и не совместится с будущим браузером | пин 2.0.7, заголовок MIT, полный откат в обычный текст по кнопке и при любой ошибке загрузки |
| Кэш: правка `book.js` не доедет до читателя | `assetVersion` включает файлы книги; `/book/*` — `immutable` в `_headers`; инвалидация через `?v=` |
| Книжный CSS утечёт на весь сайт | изолированные `.book-*`, подключение только из `book.js` |
| Строку «1916» или номер части примут за мусор и склеят с абзацем | цифровые и римские строки получают свой тип; гейт суммы текста ловит потерю, визуальная проверка — склейку |
| Тяжёлый текст (38 тыс. знаков) тормозит пагинацию | пагинация на скрытой копии один раз при включении, `requestIdleCallback` для первой отрисовки; замер — в фазе 1, при > 150 мс менять `column-width`, а не логику |

## 15. Что сознательно не делаем

- Не трогаем стихи и поэмы: у них `white-space: pre-wrap`, книжная вёрстка им вредна, кнопки нет.
- Не включаем книгу по умолчанию — ни на одном тексте.
- Не пишем свой изгиб и не берём turn.js/epub.js/canvas-решения (обоснование — общий план, п. 1б).
- Не режем страницы при сборке: ширина окна и кегль плавают.
- Не добавляем npm-зависимостей в рантайм: вендоренный файл в репозитории.
- Не переносим книгу в Бунин до приёмки здесь.
