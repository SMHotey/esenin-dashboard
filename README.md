# Есенин — дашборд-лендинг

Статический просветительский сайт о Сергее Александровиче Есенине (1895–1925): обзорная биография,
статьи о периодах жизни, люди вокруг поэта, полная библиотека произведений с каталогом,
книжные издания с партнёрскими ссылками и научная библиография.

**Стек:** статическая генерация на Node.js без зависимостей; данные — JSON + Markdown;
поиск и фильтрация — на клиенте. Сборка кладёт готовый сайт в `dist/`.

---

## Быстрый старт

```bash
npm run build     # собрать сайт в dist/
npm run serve     # локальный сервер на http://localhost:4173
npm run verify    # сборка + проверка ссылок + прод-проверки
```

Или одной командой: `npm run preview`.

> Важно: открывайте сайт по адресу `http://localhost:4173`, а не файл `dist/index.html` напрямую.
> В проекте абсолютные пути (`/styles.css`), поэтому при открытии через `file://` стили не загрузятся.

Проверки:

```bash
npm run check           # только внутренние ссылки
npm run verify          # build + ссылки + canonical/SEO/JSON-LD/книги
npm run verify:strict   # то же, но предупреждения = ошибка (CI)
```

заменив конфиг и данные (см. скилл `writer-site-factory`).

## Как обновить библиотеку

Тексты берутся из Викитеки (общественное достояние).

```bash
npm run import:genres   # обновить карту жанров
npm run import:works    # дозагрузить страницы в кэш
npm run build:works     # пересобрать data/works.json
npm run build
```

Импортёр кэширует сырой вики-текст в `data/raw-cache.json`, поэтому повторный запуск не дёргает API
за уже загруженными страницами. При большом объёме Викитека отвечает `429` — скрипт делает retry
с экспоненциальной задержкой.

**Важно:** после импорта проверьте несколько произведений вручную. Автоматическая очистка разметки
покрывает основные шаблоны (`{{poem}}`, `{{poemx}}`, `{{v}}`, `{{f1}}`, `<poem>`), но новые шаблоны
могут потребовать правки `scripts/clean.mjs`.

## Как добавить статью

1. Создайте `content/my-article.md` с frontmatter:

```md
---
title: "Название"
slug: my-article
kind: period
order: 5
excerpt: "Короткое описание для карточки и поиска."
---

Текст статьи. Поддерживаются `##` заголовки, списки, цитаты и ссылки.
```

2. Пересоберите сайт — файл подхватится автоматически (все `content/*.md`, сортировка по `order`,
   `kind: overview` всегда первая).

## Книги и партнёрские ссылки

Данные — в `data/books.json`. Поля: `title`, `subtitle`, `series`, `format`, `year`, `pages`,
`isbn`, `performer` (для аудио), `annotation`, `tags`, `highlight`, `links[]`, `searchQuery`.

```json
{
  "id": "izdanie-2025",
  "title": "Название",
  "format": "Электронная книга",
  "year": 2025,
  "pages": 170,
  "isbn": "978-5-...",
  "annotation": "Короткое описание.",
  "tags": ["лирика"],
  "highlight": true,
  "links": [{ "store": "litres", "url": "https://www.litres.ru/book/..." }],
  "searchQuery": "Есенин Название"
}
```

- Явные ссылки (`links`) приоритетнее; для магазинов без ссылки генерируется поисковая ссылка
  из `affiliate.stores.<store>.search` и `searchQuery`.
- Партнёрская метка добавляется из `affiliate.stores.<store>.tag` / `tagParam`.
- Все внешние ссылки выводятся с `target="_blank" rel="sponsored nofollow noopener"`.
- Перед списком книг обязателен блок «реклама» (`affiliate.disclosure`) — не удаляйте его.
- Обложки типографические, без издательских изображений: это сознательное решение по правам.

## Контентные правила

- **Факты.** Каждое утверждение должно опираться на источник. Спорные сюжеты выносятся в
  `data/versions.json` и не подаются как установленные.
- **Тексты.** Произведения — общественное достояние; у каждого указана страница-источник в Викитеке.
- **Фотографии.** Только Wikimedia Commons (Public Domain / свободная лицензия) с атрибуцией.
- **Научные работы.** Публикуются только метаданные и краткие аннотации.
- **Персоны.** У каждой карточки — роль, годы и источник.

## Деплой

Полная инструкция — в [DEPLOY.md](DEPLOY.md). Коротко:

1. Укажите домен в `site.config.json` → `siteUrl`.
2. Заполните партнёрские метки в `affiliate.stores`.
3. `npm run verify` (в CI — `npm run verify:strict`).
4. Загрузите `dist/` на хостинг; `404.html` используется как страница ошибки.

Готовые конфиги: `netlify.toml`, `vercel.json`, GitHub Actions workflow. Для nginx — пример в `DEPLOY.md`.

## Ограничения текущей версии

- Поиск ищет по названию и первой строке, не по полному тексту произведений.
- Нет CMS-админки: контент правится в JSON/Markdown и пересобирается.
- Английская версия не сделана, но в данных и URL заложена возможность i18n.
- `data/raw-cache.json` не коммитится (большой); при первом импорте скачается заново.
- OG-изображение 1200×630 собирается из портрета и данных: `python scripts/make-og.py`
  (нужен Pillow). После смены домена пересоберите картинку.
