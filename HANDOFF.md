Открывать только через `http://localhost:4173`, не через `file://` — в проекте абсолютные пути.

---

Проверка партнёрских ссылок: `scripts/check-affiliate.mjs` берёт все товарные ссылки из
`data/books.json` и `data/audiobooks.json`, ходит по редиректам и различает три состояния:
ссылка мертва (404/410, товар снят — карточку убирать из данных), ссылка подозрительна
(увела на поиск, потеряла `erid`/`utm`, товар OutOfStock) и «не проверено» (403 антибота).
Отчёт пишется в `reports/affiliate-report.json`. В `deploy.yml` это отдельный job `affiliates`
после выкладки: красный статус значит, что пора править данные, на публикацию он не влияет.
Важно: из сети GitHub Читай-город отдаёт 403 на все запросы, поэтому ежедневная проверка
всех ссылок идёт с домашней машины (cron 9:00, молчит при норме, пишет в Telegram при проблеме).

## 3. Архитектура

- Генератор: `scripts/build.mjs` (Node.js ≥ 20, без зависимостей).
- Данные: `data/*.json` + `content/*.md`; статьи подхватываются автоматически.
- Идентичность автора — в `site.config.json` → `author` (имя, падежи, годы, места, портрет,
  подвал). Генератор не содержит хардкода «Есенин», поэтому пригоден для других писателей.
- `src/styles.css`, `src/app.js`, `src/theme.js`, `src/art/desk-404.svg`.
- Версионирование ассетов: `?v=<hash>` от содержимого CSS/JS — кэш сбрасывается сам.
- `scripts/verify.mjs` — проверки прод-готовности (SEO, canonical, JSON-LD, ссылки, книги, служебные файлы, запрещённые редакционные формулы).
- `scripts/text-audit.mjs` — филологический контроль журнала: методические и роботные формулы, объём, конкретность источников, сверка цитат с корпусом библиотеки.
- `scripts/last-updated.mjs` — даты последнего изменения по разделам из истории git → `data/updated.json` (запускается перед сборкой). Подвал и `lastmod` берут дату правки материала, а не дату сборки; в мелком клоне используется закоммиченный манифест.

### Книги и аудиокниги

- Бумажные издания — «Читай-город»: готовые партнёрские ссылки вида
  `https://www.chitai-gorod.ru/r/XXXX?erid=…` (метку подставлять не нужно, erid уже внутри).
- Аудиокниги — ЛитРес, оффер `litresru` в AdvCake. Собираются скриптом
  `npm run import:audiobooks` (`scripts/import-audiobooks.py`): поиск ЛитРеса → разметка
  schema.org Audiobook → Cakelink API (`https://cakelink.ru/link?dl=<url>&pass=<ключ>`)
  отдаёт партнёрскую ссылку под каждый товар с метками и erid. Ключ AdvCake лежит в
  `.secrets/advcake.key` (каталог в `.gitignore`) или в переменной `ADVCAKE_API_KEY`.
- Маркировка рекламы своя у каждого магазина: `affiliate.advertiser` (ООО «ГРАМОТА») и
  `affiliate.stores.litres.advertiser` (ООО «ЛИТРЕС», ИНН 7719571260).
- Цены не публикуются (`affiliate.showPrice: false`): карточка аудиокниги показывает чтеца,
  длительность и год записи.

## 4. Принятые решения

- Полные тексты произведений (общественное достояние), с указанием источника.
- Фотографии — только Wikimedia Commons (PD/CC) с атрибуцией.
- Научные работы — только метаданные и аннотации.
- Спорные факты — в разделе «Версии»; в основных текстах только подтверждённое.
- Без комментариев и пользовательских данных.
- Только русский язык; i18n заложена в структуру, но не реализована.
- Статика + Git, без CMS и серверной БД.
- Книжные обложки — типографические, без издательских изображений (права на дизайн).
- Пометка «реклама» и раскрытие партнёрских ссылок — обязательны на всех страницах с ними.

## 5. Что осталось сделать владельцу

1. Заменить `siteUrl` (`https://esenin.example`) на боевой домен.
2. Заполнить партнёрские метки магазинов в `affiliate.stores`.
3. Подключить аналитику (Метрика/GA) и, если нужно, страницу политики конфиденциальности.
4. Пересобрать OG-картинку после смены домена: `python scripts/make-og.py`.
5. Проверить книги: актуальность ссылок, ISBN, наличие в магазинах.
6. Прогнать `npm run verify:strict` перед деплоем.
7. Книжный режим: матрица пройдена только в Chrome — прогнать Firefox, Safari (десктоп), iOS Safari и
   Android Chrome и проверить скринридером (NVDA).

## 6. Известные ограничения

1. Поиск ищет по названию и первой строке, не по полному тексту.
2. Нет A–Z-страницы (есть сортировка по алфавиту).
3. Нет CMS-админки — правки в JSON/Markdown + пересборка.
4. Slug’и произведений — кириллицей (унаследованы от Викитеки). Работает, но для аналитики
   и внешних ссылок при желании можно добавить транслитерацию.
5. Нет автотестов вёрстки и скриншот-регрессии.
